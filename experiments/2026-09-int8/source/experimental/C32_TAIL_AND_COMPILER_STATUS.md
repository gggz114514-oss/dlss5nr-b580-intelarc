# 隔离 Triton3.8 整网验证与 C32 尾段结果（2026-09-09）

用户最新要求：暂不继续发布，等阶段性成果再发。本轮仅保存本地实验；不更新 GitHub 仓库或 Release。已发布版本没有删除请求。完整迁移目标仍未完成，第一性能目标仍是在同 NR 输入尺寸、同计时范围下追平4060。

## 本轮结论

隔离编译器的收益可以复现。保持 native-half 快速模型代码不变，不安装 C32 tail，按3.7.2、3.8、3.8、3.7.2顺序运行4个独立进程；每进程180个reset和180个连续帧，共1440个完整输出哈希全部与固定3.7.2记录一致。使用相同256×256原生half输入纹理、零运动和默认SDR。计时包含完整NR、历史提交和GPU完成，排除IO、上传、JIT、校验、残差缩放、运动估计及游戏竞争。

| 编译器 | reset完整host均值 | 连续帧完整host均值 |
| --- | ---: | ---: |
| 原安装3.7.2 | 18.348809ms | 22.322634ms |
| 隔离3.8 | 16.248869ms | 20.252519ms |

连续帧耗时降低9.2736%，速度比1.1022。ABBA可以减少进程顺序漂移影响，但不是同进程交替编译器。四个进程按各自租约完成时间严格串行，全部returncode0，原环境未升级。PyTorch仍为2.13.0+xpu，只有Triton包选择不同；这是本模型/硬件/编译缓存下的结果，不是所有工作负载的版本性能保证。

4060固定参考的同口径连续帧完整host为3.566807ms。新B580实验仍是其5.6781倍耗时，尚未追平。4060数字来自已验证的固定参考实验，本轮没有重新运行参考机。B580采用已审核的FP16快速算术，并非与原生NVIDIA输出逐字节相同的精确分支。

静态主体诊断也复现下降：旧版连续图两进程中位数15.964500/15.953870ms，新版13.853480/13.850340ms。这些不是完整NR时延或设备忙碌时间，不能与4060 GPU事件数字混除。每个图50次重放、每组10次后完整读回，共5次完整读回。

## C32尾段融合的实际收益

新增 `c32_tail_adapter_v1.py` 只接管4个encoder和3个普通decoder C32SwinBlock的实例方法。pre、上采样、post保留自己的执行合同；按模式/后端/设备/类型回退，保留固定LUT身份和版本检查、实例所有权及异常恢复。统计维持原模型逻辑算术计数，不能把逻辑计数当成物理kernel数量。

原始完整主体在隔离3.8下先对照冻结3.7.2完整输出通过；再加入tail，同样完整字节一致。5轮交替静态主体中位数13.736070→13.670160ms，只节省0.065910ms，约0.48%。冻结原报告的 `complete_replay_outputs_verified=100` 命名过强：实际完成100次重放，在每10次之后读回一次完整输出，总计10次完整读回，另有3次eager完整检查。补充CPU审计明确更正计数含义，原始报告和源码不覆写。

完整NR256+1080p残差合成的3轮13帧，共78次全输出/低分辨率NR/历史/种子检查通过；常量替换、原位版本变化、progress回退、返回值与私有历史所有权均通过。包含reset的完整均值20.033551→19.776138ms（约1.3%）；连续帧部分20.648594→20.384042ms。

但同256原生输入的720次完整NR配对测量，基线20.179989ms、tail20.214267ms，tail没有稳定完整收益。相邻轮次胜负变化，因此不将tail安装成正式快速路径，不以单模块13.69%或初筛24%宣称整网提升。本轮有可靠价值的是隔离编译器约9.3%的完整耗时下降；tail作为已验证实验保留。

## 时序与画质

隔离3.8+tail完成390帧独立连续历史验证。每个完整256×256half NR张量逐字节相同，每个完整1920×1080 FP32合成张量的所有字节参与SHA256并匹配已审核视频记录。重置回到第一帧、保持旧返回值、修改调用方返回值不影响历史、输入与LUT均通过。重用旧完整低NR和运动数组，没有重新编码视频或倾倒整帧数组。

CPU审计重新读取780个完整唯一数组共2,503,020,263存储字节，核对GPU比较和全帧哈希收据；它不是独立CPU模型重算。按用户对一致输出的豁免，不发起新肉眼审核。上述覆盖不证明任意尺寸、HDR、控制参数组合或所有NaN编码均已验证；精确分支35文件保持原样。
