## 复测设计

保留 V1 三个配置、原 GPU 算术、同一 16 块真实输入、编译资源检查、CPU 整数
抽查、全零/取反/恢复控制和有效区域误差统计。新报告进一步强制其输入、二进制、
权重、误差和所有候选输出与 V1 相同。没有重新量化，也没有更换候选配置。

一次有界运行包含三个计时块，全部报告，不挑最快样本：

1. 原协议复现：12 轮轮换，每个样本 32 次重放，每路线结束后检查输出。
2. 持续预热协议：每个路线每次测量前先重放 64 次，等待完成；随后计时 128 次，
   共 12 轮。该轮四条路线都计时完才检查输出，减少样本间 CPU 摘要造成的空档。
3. 再做一次原协议：12 轮、32 次、逐路线检查，判断前后时间漂移。

每次计时均包含末尾 GPU 完成等待，不使用 GPU profiler/events。预热明确排除在
正式耗时外；每帧输入量化仍在图中，始终计入。第二、三块保存原始纳秒总时长，
固定审核重新计算每次平均耗时、中位数、轮次胜数，并核对全部输出验证记录。
CPU 预检使用虚拟图和时钟，验证预热/验证不被混入计时，以及输出损坏会失败。

该设计只能提高局部计时结论可信度，不保证排除外部 GPU 竞争，也不能直接推导
完整时序模型收益。保持 32 与 128 批次结果分别解释。只有收益值得继续时才接入
完整模型并制作人脸/运动视频交用户审核；默认和精确分支保持原样。

等用户确认其他 3D 负载已停止后才启动。源文件执行后冻结。结果在 D；不转储
原始张量，不生成视频。主助手实际启动，
现有 Luna/max 只监控并执行固定审核；异常立即报告，不自行修复、重试或另加实验。
