# INT8分支实验

最新实时路线试验见 `RESIDUAL_SCALE_STATUS.md`：完整 NR 在 256×144 有效画面执行并重建到1080p，处理路径实测约45ms，仍未达到实时；残差新画面尚未长片审核。分块测试见 `DENSE_TILE_STATUS.md`：仅480p INT8有约2.9%耗时收益，FP16/1080p无明显收益，不能靠此达到实时。

完整1080p时序及控制适配器结果见 `LONG_1080_AND_CONTROL_GRAPH_STATUS.md`。用户现已回复“两种都可接受”，两种快速精度的完整390帧通过人工审核；默认长片使用v6。新v7在七组256p精确控制中验证，拦截基类计算体以保留派生类控制写入；仍是实验接口。

当前完整分辨率组合使用 `graph_front_v6`、`strided_batched_v2`、`window_layout_v1`，稠密矩阵提供器仍继承 `fused_cached_matrices_v2`。480p INT8可选 `tiled_matrices_v1` 并已完成243帧同字节复查；不建议将它当作FP16/1080p的提速措施。完整243帧480p和390帧1080p的两种快速精度已获用户认可；生产集成仍待完成。以下保留首轮算术原型的说明，其“未审核”状态不代表当前长片结论。

本目录只属于`nr/int8`，共享起点为精确分支提交`34f0430`。运行时显式读取相邻`nr-b580`中的既有模型和参考资产；实验结果及编译缓存存储D盘，完整相同数组共用内容寻址文件。

当前算术候选`fast_matrices_v3.py`保留原模型图、FP8边界和K8精确路径，提供两种用于对照的模式：

- `fp16_xmx`：K16稠密矩阵和批矩阵使用FP16乘法、FP32累加，输出FP16。
- `int8_dense`：稠密矩阵使用对称W8A8、INT32累加；激活逐行、权重逐输出通道缩放。缓存不可变模型权重。注意力批矩阵保持FP16，其他敏感运算保持原实现。这不是全图整数表示。

矩阵相加和半精度舍入与原NVIDIA规则存在差异。这两个模式仅在实验上下文内替换算术入口，不能被解释为已完成迁移或通过用户画质验收。当前未加入降分辨率重建。

`validate_matrices_v5.py`的16项检查已通过，覆盖零行、尾块、非连续输入、批矩阵、带初始累加值及真实INT8量化。独立CPU量化与普通矩阵计算作为算术参考；编译IR保留Intel子组矩阵乘加和DPAS布局。小矩阵结果不证明完整NR画质。

前四次检查的源码和失败报告保留：第一次误查LLVM中DPAS字符串，第二次要求近似除法缩放系数完全相同，第三次发现INT8累加返回类型需显式指定，第四次发现近似除法改变量化舍入边界。最终内核使用正确舍入除法及显式INT32累加类型。

`benchmark_full_precision_v1.py`比较三个独立MotionNR实例的真实连续帧和末尾重置，核对精确模式的4060字节、输入不被修改、输出不与私有历史别名、失败调用不推进状态。三个实例轮换执行顺序。耗时包含完整模型及同步，不包含上传、落盘、验证、启动权重打包和首帧JIT；还不是端到端产品帧率。

`audit_and_render_precision_v1.py`重新读取已保存的完整输出，核对摘要与误差，生成原图／4060与精确后端／FP16／INT8四格对照。短片慢放用于审核，不是推理FPS，也不替代长视频时序验证。
