# 基于数据流证明的 FP8 图改写（2026-09-09，本地）

第一批执行图结构优化已通过完整验证：在同轮配对的固定 NR256 输入上，连续帧完整调用从 **12.850255 ms 降到 12.345622 ms**，减少 0.504633 ms（3.9270%），三轮均变快。当前实验执行栈在 d52983f 的全部优化之外加入 `fp8_graph_rewrite_v1.FP8GraphRewrite`。

它删除 231 次有证明的重复 FP8 量化，完整主体的 Triton 调用请求从 986 次降到 755 次，独立量化从 463 次降到 232 次。网络、权重、累加和舍入规则均保留。不是新增 INT8 计算，也不是改小模型或蒸馏。

精确后端的 35 个文件未改。本次字节一致指相对已接受的 FP16 快速路线，不能据此宣称快速路线已与 NVIDIA 原生逐位一致。生产接入、更多精确尺寸/控制/HDR 验证及性能持平仍未完成。代码和实验仅保存本地，没有发布或参考机操作。

## 从调用次数到可靠数据流

`quantization_dataflow_v1.Dataflow` 使用 StorageWeakRef 跟踪存储对象的生命周期，以存储代次、写入版本和生产者编号标识值。它不把可复用的显存地址当作身份，也不依赖 inference tensor 的版本计数器。弱引用不延长 GPU 数据的生命周期。

对当前 21 类 Triton 内核，显式声明已经查阅源码的输出参数和 FP8 输出契约；未知内核或绑定失败直接拒绝。只有覆盖整个连续 half 存储的写入能建立 FP8 数值域证明。ATen schema 中的写入使整个存储的证明失效；只读视图共享存储关系。已知保持值的复制、布局操作和补零，可以继承 FP8 证明。

每条读取记录生产者、存储代次、写入版本、dtype、形状、stride、偏移及逻辑字节数。13 段跟踪共认证 5013 条读取边，所有阶段的完整输出匹配无跟踪执行和旧阶段参考。次数仍是 Triton launch 请求和 ATen 操作，不能当作完整原生 GPU 轨迹或耗时比例；逻辑字节数也不是实测显存流量。

分别执行 13 段时找出 212 次重复量化；整段执行还能证明跨阶段的 19 次，所以完整图合计消除 231 次。全图比逐段检查多消除的部分来自数据流连续性。

## 如何改写而保持行为

`RewritingDataflow` 只在构建主体 GPU 图时替换量化入口。已知 half 输入处于同一 FP8 数值域时，返回保持相同布局约定的连续张量；已有的逻辑 FP8 dispatch 记录仍保留。它保护被借用的存储代次，后续任何别名写入都会被拒绝。ATen 写入在执行前拒绝，Triton 写入在启动前拒绝。

图构建完成后直接重放改写的 GPU 图，每帧不重新运行这套 Python 值分析。已有 GraphFront 的外部输入、图池外输出、私有历史、常量版本和调用方所有权约束保留。

适配器限定为已拥有模型、fp16_xmx/triton 模式、XPU RGB 256×256×3、front 320×320×16、half 输出。其他情况走原方法。它仍依赖现有串行实验会话，不宣称已经提供并发生产后端。

所有 65,536 个 half 位模式均通过实际 GPU `q(q(x)) == q(x)` 字节比较，包含 NaN、Inf 和正负零。对阶段跟踪判定的全部 212 次重复量化，另保留实际源/目标张量至阶段结束，逐字节比较二者，避免只依赖标签判断。

保护检查通过：未借用值被修改后证明失效；借用别名写入在修改前被拒绝且原数据不变；非连续输入消除量化后仍返回连续且相同的结果；存储弱引用过期后，新存储不会继承旧证明。13 个阶段改写前后完整输出一致，整段重置和连续图也匹配原参考。

## 下一批图改写

剩余量化的已观察生产者包括普通矩阵、MLP 投影、窗口 unpack 和 ViT 合并。当前未改写阶段的 463 次量化中，有 68 次直接来自普通矩阵，36 次来自批分支投影，46 次来自 unpack，16 次来自 ViT merge；这些不是可直接融合的最终数量。

下一步采集已采用改写后的完整主体数据流，保留可靠的生产/消费边和必要常量参数。对矩阵、投影的最终 half 存储后仅被相同 FP8 量化消费的值，评估把 FP8 舍入合入生产者存储。必须排除仍有原始 half 消费者的输出，例如 skip 或池化分支；不能只因量化紧跟矩阵就改写。现有阶段边界不能证明跨阶段消费者，需使用完整主体的图。

当前批次的必要检查已经完成；后续以新改写和新问题为依据继续测试，不重复已有 GPU 验证。本次只是执行架构优化的第一批，完整迁移目标继续保留。
