# QKV 归一化、FP8 与窗口整理融合（2026-09-09）

本轮在已有 C512 分组融合和多头批量执行基础上，将每个 MultiHeadAttention 的 Q/K 归一化、Q 的每头缩放、Q/K/V 的原 FP8 边界及窗口排列合成一次 GPU 调度。NR256＋1080p 残差路径连续帧从30.073ms降到29.152ms，约减少3.1%；仍未达到60帧预算。

## 实现与适用范围

`fused_qkv_pack_v1.py` 直接读取连续的 H,W,head,3,32 半精度投影，通过模型自有像素排列写出三个 head,row,col,64,32 张量。保留原 half FMA、XOR4/2/1 半精度归约、rsqrt夹取、NaN位处理、每头缩放和E4M3转换，禁止浮点融合重排。QKV投影、注意力核及逆排列沿用上一版。候选行块8/16/32/64，实测16最好，使用固定16。

`qkv_head_layout_v1.py` 仅更换所属模型的 FP16 多头路径，保留原逻辑运算计数；这些计数并非物理GPU调度数量。C32单头、ViT和INT8路径未修改。仍是串行实验上下文，没有生产API或多会话并发保证。

## 原语与完整路径验证

真实NR256连续帧捕获52个多头模块，另加覆盖65536种半精度位模式的合成张量，以及144×240、两头的重复真实数据。54组数据×4种行块共216个完整Q/K/V比较全部通过，4种行块的完整网络主体输出也一致。非有限位模式仅验证原语，不扩大NR的有限输入合同。

原语静态图计时包含每个版本相同的输出复制。代表性的两头/四头/八头真实模块，原路径53.365/37.525/31.530µs，16行融合34.570/22.365/20.315µs；合成大尺寸397.370→213.985µs。这些数字不是整帧速度。所有候选报告spill为0；编译器register为0的字段不能解释为物理零寄存器。

整帧配对采用3轮×13帧×2个独立模型，共78次完整输出比较；执行次序轮换，共享认证只读常量及串行临时图内存池。完整输出、私有历史、种子/重置、输入不变、持有输出、进度回退和逻辑dispatch全部通过。

主计时包含GPU模型、动态前端、图复制、历史提交、完成同步；残差路径另含GPU图像/运动缩放及1080p合成。排除运动估计、上传、JIT/捕获、验证、IO、呈现和游戏并行争用。光流复用用户已有GPU链路，不继续优化CPU DIS。30ms附近的数字不代表全尺寸1080p网络或最终游戏帧率。

全尺寸480p完整243帧与此前批准FP16输出及私有历史逐字节一致，完整回读486份输出/运动数组、复用854,492,705字节旧数据；未新增视频或输出副本。末尾重置、持有第0/120帧输出、输入不变和自有连续历史也通过，可复用原肉眼验收。其同步模型调用均值94.122ms仅作长片验证诊断。

完整1080p的390帧也全部通过上述检查，复用原批准FP16输出及私有连续历史，末尾重置成功、两张图共393次回放。同步模型调用均值461.270ms，峰值分配2,303,418,368字节、保留4,775,215,104字节；这是长片验证进程诊断，没有同进程的1080p基线配对，不能据此推断大尺寸提速比例。CPU审核完整回读780份输出/运动数组，复用6,188,940,320字节旧数据。

低分辨率残差模式本身仍未获得完整390帧的新画质批准，不能用全尺寸FP16验收代替。没有新的4060长片捕获声明，也不声称迁移已完成。

## 更新后的热点

`profile_fused_body_stages_v2.py` 使用当前完整融合栈，13个阶段各进行7轮×10次静态图回放。阶段图完整输出与同算术即时输出一致，组装的最终图像与既有连续帧参考字节一致；模型私有历史及种子保持不变。保存的四份输入直接内容寻址复用。

整体静态主体中位22.705ms，阶段中位数之和21.984ms；后者受到分段调度、同步和缓存状态影响，不能替代前者或整帧延迟。

| 阶段 | 中位耗时 |
|---|---:|
| pre | 3.027ms |
| encoder C32 / C64 / C128 / C256 / C512 | 1.244 / 0.799 / 1.000 / 1.745 / 1.579ms |
| ViT八块，64 tokens | 3.823ms |
| decoder C512（含输入）/ C256 / C128 / C64 / C32 | 1.603 / 1.721 / 0.996 / 0.814 / 1.246ms |
| post | 2.388ms |

C512两端已降到合计约3.18ms，下一步应转向ViT与pre/post，三者仍合计约9.24ms。ViT的四分区投影必须保留每个分区的独立累加和顺序半精度合并；可以测试把分区计算和合并放入一个调度，不能直接换成普通全K累加。pre/post中的C32单头仍有分块归一化及窗口整理，复用此次多头融合时需保留32768行边界和逻辑计数。真正更小或矩形NR输入需先取得原生尺寸/填充/时序证据，不能直接放宽尺寸表及token检查。
