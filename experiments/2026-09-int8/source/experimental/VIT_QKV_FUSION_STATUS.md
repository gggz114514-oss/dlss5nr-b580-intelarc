# ViT QKV 融合：本地阶段记录（2026-09-09）

在上一版历史采样融合的基础上，将所属模型的 ViT Q/K/V 分段投影、半精度合并、归一化、query 缩放和 FP8 转换压缩为两次 GPU 调度。此次同轮 NR256 完整调用对照中，连续帧均值从 14.779508 ms 降到 14.268516 ms，减少 0.510992 ms（3.4574%）。720 次完整输出比较与独立 390 帧视频检查通过，没有新增画质变化。

固定 4060 参考仍是同输入尺寸、显存输入、完整主机调用与完成等待的 3.566807 ms；本次 B580 为其 4.00036 倍。尚未达到性能持平或完整迁移目标。按照用户要求，本次只保存本地成果，不更新公开仓库或 Release。

## 用当前数据选择目标

先在隔离 Triton 3.8、K8 平铺和历史采样融合组成的当前栈上重新测量 13 个阶段，静态完整主体约 12.325620 ms。8 个 ViT 块约 2.027290 ms，encoder C512 约 1.234190 ms，decoder C512 约 1.249010 ms。分段诊断有独立图边界、完成等待和缓存差异，不能把分段之和当作最终整帧延迟。

随后拆开第一个实际 ViT 块，并核对原模块的全部七个返回张量与完整八块输出：

| 首个 ViT 块的阶段 | 静态诊断耗时 |
| --- | ---: |
| FFN expand 和 cubic/FP8 | 67.790 μs |
| FFN contract | 36.070 μs |
| QKV 投影和准备 | 78.430 μs |
| 注意力 | 37.420 μs |
| 输出投影 | 23.110 μs |

这说明 QKV 周围的分段投影和准备操作值得融合。没有改动运动估计、模型权重、输入尺寸、历史采样或精度策略。

## 实现与适用范围

`fused_vit_qkv_v1.py` 的第一个核心并行计算两个独立 K512 分区，各自保留 BK32 FP32 累加与写回 half 的边界。按原输入的行跨度读取两个半宽分区，避免额外生成两份连续输入副本。选择 BM32/BN64、4 warps。

第二个核心先进行原次序的 half 合并，然后执行原 C32 归一化、query 的 5.65625 倍 half 舍入、每头 query scale 的独立 half 乘法和 FP8 转换。保留原 `_half_fma_value`、XOR 归约、倒平方根和 FP8 helper，没有把两个独立分区改成一次全 K 累加。两次调度替代原来多次调用，并不意味着逻辑矩阵运算数量变成两次。

`fused_vit_qkv_adapter_v1.py` 只替换所属模型、FP16 快速模式、Triton/XPU 上 64×1024 输入的 ViT 方法；其余模型、模式、尺寸走原方法。返回原有 hidden、mlp、query、key、value、attended、output 七个结果，并保留逻辑操作计数。用现有串行作用域及完整模型常量/图所有权检查管理生命周期。

本次优化组件加入已批准的 NR256 快速路线。正式精确后端的 35 个文件未修改，INT8 路线未改变。相对 NVIDIA 原生的既有 FP16 差异仍存在；“字节一致”指本次优化前后及已批准快速路线之间一致，不是宣称快速模式已与 NVIDIA 字节一致。没有将该组件推广为所有 token 数、非有限输入、HDR 或全部控制行为都已验证。

同口径连续帧三轮均值：旧版 15.072770 / 15.015182 / 14.250572 ms，新版 14.474117 / 14.514575 / 13.816855 ms。前一轮实验的旧版绝对值约 14.37 ms，与本轮基线存在运行间波动；提速比例使用本轮配对结果，不能直接用两次运行的绝对值相减。

完整 NR 计时包含状态提交与完成等待，排除上传、运动估计、解码、残差缩放和呈现。残差流程的计时额外包含颜色/运动缩放及 1080p 合成。没有将这些数字解释成实际游戏端到端帧率。GPU 事件区间只是主体诊断，不是完整 NR 纯计算忙碌时间。

- 从当前模型的八个实际块取得 QKV 输入；4 个 tile 配置的 32 组完整 Q/K/V 比较全部匹配。每组还比较图捕获输出和各计时组完成后的全部输出，验证输入与常量未变及持久输入输出位于图池之外。保存后审计重读 48 个数组，合计 27,388,138 存储字节。
- 模型级验证八个块全部七个返回张量，并核对八块最终输出。零输入、有符号有限输入、非连续输入、其他模型实例和 96 token 回退五组均核对全部七个张量；作用域退出后原方法恢复。
- 78 个完整 NR/1080p 输出通过，同时通过独立历史、重置、调用方所有权、进度回退和常量变化拒绝检查。进度回退中融合组件实际执行八次；原路径执行零次。
- 完整 390 帧连续历史通过：低分辨率 NR 全部字节、每帧完整 1080p FP32 输出哈希和已批准视频对应结果一致，末尾重置复现首帧。不生成新视频或完整大帧转储。按用户的字节一致豁免，不再要求肉眼审核。
- 同原生输入的 720 次完整 NR 输出通过，逐次匹配优化前版本及冻结的 Triton 3.7.2 对应快速输出。重置、独立输出、输入/LUT 不变与图所有权检查通过。

CPU 审计认证源文件、报告、结束状态，并重读引用数组；390 帧审计复读 780 个数组、2,503,020,263 存储字节。这些审计不是独立执行 NR 数学的 CPU 实现。

## 下一步

当前选定栈在上一版历史采样融合之上加入 `FusedVitQKV`。本次已完成针对这项改动的验证，不因准备收尾而重复 GPU 测试。继续定位当前栈剩余的矩阵开销：首个 ViT 的 expand 约 68 μs，C512 两端合计约 2.48 ms；其他仍使用通用 BM16/BN32 的 FP16 矩阵值得用当前实际操作数和调用次数分析，再决定 tile 或融合策略。历史 3.7.2 的全尺寸实验不能直接代表当前 3.8/NR256 栈。

完整迁移仍包括生产 OptiScaler/XeSS/ComfyUI 接入、更宽的尺寸、HDR/控制行为以及性能目标；本地 NR256 快速组件进展不替代这些要求。
