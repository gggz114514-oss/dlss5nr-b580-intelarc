# DIS 光流耗时复测（2026-09-09）

**后续用户纠正：隔壁项目已有经其验证的快速 GPU Block 和 GPU DIS，授权直接复用。停止为产品开发或优化 CPU DIS 前端，主力回到 NR 执行。** 本文只记录生成参考输入的 CPU 路线耗时，不能用它代表既有 GPU 光流链路。已找到离线工具箱的共享 GPU MotionPacket/FrameLease 契约和严格 DIS provider；接入边界见 `ROI_AND_GPU_FLOW_REUSE_STATUS.md`。

当前约35.36ms的 NR256＋1080p残差路径不包含光流；原始1080p CPU DIS两线程本次仅创建和计算就需要131.23ms。即使通过流水线重叠CPU/GPU，这条CPU生产路线也无法供给每秒30或60帧。这里没有测量实际游戏整链速度。

使用已认证的1080p输入第180至191帧，11个连续帧对、3轮，各配置按帧轮换顺序，全部在CPU运行，OpenCL关闭。各配置预热两次。解码、核验和存储在计时外；“CPU路径”包含当前帧灰度转换、可选AREA缩小、DIS MEDIUM创建/复用与calc、FP16转换，前帧灰度缓存。表中不含把所得光流进一步映射到NR模型网格及上传。

所有198次运行得到有限FP16光流，各配置同帧三轮字节稳定。三种全尺寸配置共99次输出与原记录的完整FP16光流相同。这只证明当前视频、OpenCV构建和CPU上的结果，不外推到所有输入或线程设置。

低分辨率不能直接采用为画质已验收路径。将光流用CPU AREA滤波映射到256×144并按XY像素单位缩放后，相对全尺寸DIS的平均端点差分别约1.04、3.54、5.32个低分辨率像素。这个指标不是引擎真实运动误差，也不是NR图像质量；CPU滤波亦不宣称与现有GPU滤波逐字节相同。仅凭运行快，不能判定遮挡、手部运动和拖影可接受。66份完整低分辨率诊断光流保存在D盘，并已重新读取核验；本轮没有生成或审核新的NR视频。

此前对低分辨率CPU光流的探索不再作为后续实施方向。OptiScaler路径可接入可用引擎运动向量；视频或屏幕捕获复用用户已有GPU provider，并验证与NR之间的方向、单位、分辨率和资源同步。新链路的NR输出如不同，仍需自己的时序比较。精确参考保留已认证的原光流。

网络本身仍约28.64ms，因此光流问题与网络执行问题都要解决。不能把取消DIS描述成已经达到60帧，也不能把本次CPU耗时与以前GPU耗时相加称作整链实测。正式接口、默认配置和原有精确算术文件均未修改。
