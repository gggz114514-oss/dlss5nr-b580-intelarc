# 原生半精度 cubic 优化（2026-09-09，本地）

当前 NR256 快速路线的完整连续帧调用，在同轮配对测试中从 13.495988 ms 降到 13.223358 ms，减少 0.272630 ms（2.0201%）。三轮均有收益。720 次完整输出比较、390 帧独立时序及 78 次完整残差流程验证通过。源代码及记录仅保存本地，不更新公开仓库或 Release。

正式精确分支的 35 个后端文件保持原样。此次“字节一致”指与优化前、已获用户接受的 FP16 快速路线一致；不表示快速路线已与 NVIDIA 原生逐位一致。完整迁移、生产接口与性能持平仍未完成。

## 主体和外围的当前拆分

用户本轮询问两部分各花多少时间。下表都是 NR 实际输入 256×256，连续帧口径：

| 场景 | 主体完成时间诊断 | 完整调用 | 主体以外的近似差额 |
| --- | ---: | ---: | ---: |
| 与 4060 相同的固定 NR256 输入 | 11.117550 ms | 13.223358 ms | 2.105808 ms |
| 1080p 视频画布，NR256 + 残差合成 | 11.001680 ms | 13.811118 ms | 2.809438 ms |

差额来自分开执行的主体诊断与完整调用统计，不是同一帧分段打点后精确可加的结果。原生参考场景主体是 10 次完成等待的平均值，视频主体是五组十次重放的中位数；完整调用是独立连续帧均值。可据此估算主体占八成左右，不能把两个场景相减来声称缩放/合成精确用了 0.59 ms。

这里“主体”是已捕获的静态 NR 主体图，包含模型编码器、ViT、解码器以及图内前后处理；不是只有矩阵乘法。“主体以外”还包含动态前处理、历史采样、常量/所有权检查、调度、状态提交及完成等待等；第二行还包含颜色/运动缩放与残差合成。两行均不包含解码、光流估计、上传、显示或游戏资源竞争，不能作为最终游戏全链路帧时间。主体事件诊断约 10.93 ms 包含调度区间，不视为纯 GPU 忙时。

4060 同输入完整调用参考仍为 3.566807 ms，本轮 B580 为其 3.707337 倍。480p 和 1080p 原生参考不参与这个倍数。

## 验证 unary cubic 的原生 half FMA

旧实现为模拟准确 half FMA，先用多条 FP32 指令算误差补偿，再修正半精度舍入。三个 cubic 系数 0.055908203125、0.447265625、0.89453125 都可由 half 精确表示。

新增 `native_half_cubic_v1.py` 只替换这个特定 unary 调用：保留 [-4,4] clamp、两次独立 half FMA 舍入、最后 FP32 乘法转 half 和既有 FP8 转换。没有全局替换通用 `_half_fma_value`。

枚举全部 65,536 个 half 位模式，包括非有限值与正负零；同时测顺序和打乱加尾部输入、三种 block 宽度。新算术、旧 GPU 算术、认证表三者 18 份完整输出全部一致。保存后 CPU 审计重新按输入位索引认证表，逐字节比较保存的完整输出。LLVM IR 确认新实现含 `llvm.fma.f16`。

单独的 524,288 元素激活，旧补偿/新原生/查表中位耗时分别约 9.585/5.577/3.885 微秒。这种顺序输入下的独立激活性能不代表融合矩阵中的访问分布与收益，所以没有直接据此选择整个模型路径。

## 实际融合矩阵选择

从当前已包含 dense 分块、历史融合和 ViT QKV 融合的模型采集 13 个真实尺寸类别：C32 10 次、批分支 36 次、C512 16 次。采集完整操作数和输出，记录原始 stride，总计 50,161,600 原始字节，低于 128 MiB 限额。审计复读 73 个唯一数组，38,727,651 存储字节。整段主体最终输出、历史和 seed 一致。

三类新内核从旧实现复制，只替换特定激活；保留 DPAS 的 BK32 顺序、每次 half/FP8 边界、skip 和累计顺序。查表 API 仍保留原常量注册及身份/版本检查。共 41 次完整 eager 比较通过，另验证图捕获和五组计时末尾完整输出、原始输入不变与图池外持久输入输出。每组四次调用、十次重放，轮换/反转计时顺序。

仅选择中位耗时至少减少 5%、且每轮均减少 2% 的配置：

- C32：102400、25600、28224、26880、107584 行，BM32/4 warps/stage1，覆盖 10 次调用。
- C256 批分支：576 行，pair BM32/stage1，projection BM16/BN64，覆盖 16 次调用。
- C512：144 行，BM16/BN32/stage1，覆盖 16 次调用。

7 类尺寸合计覆盖每帧 42 次，按局部调用数加权估算节约 0.385222 ms。C64 等未稳定变快，保留查表。`native_cubic_adapters_v1.py` 只在已拥有模块、FP16 快速模式、XPU 连续 half 输入及已测尺寸上选择新路径，其他情况继续父实现。更改参数的 C32 配置也回退。

7 组实际模块选择和每类未知行数、非连续输入、FP32 输入共 9 条真实回退通过，均比较完整输出。完整进度回退确认每帧新 C32/批分支/C512 调用分别 10/16/16 次，原逻辑 dispatch、dense 分块与 K8 数量不变。

NR 连续三轮：旧 13.515200 / 13.717293 / 13.255470 ms；新 13.233258 / 13.493350 / 12.943465 ms。历史记录 13.296283 ms 是另一次测量，不能用它与本轮相减推算优化收益。

78 次完整残差输出与低 NR 输出匹配固定参考。390 帧独立连续时序的全部低 NR 字节与全部 1080p FP32 合成哈希匹配已审核视频；重置复现首帧。720 次固定原生输入的完整 NR 输出与同轮上一版、冻结 3.7.2 快速结果均一致。调用方输出所有权、历史、seed、非法运动和常量变化拒绝检查通过。保留用户对字节一致版本免肉眼复核的要求，没有重新编码视频或保存大帧副本。

新内核计数中的 C32 60 / 批分支 96 / C512 96 是图构建阶段六次主体执行的计数；后续由图重放执行，不是整段视频仅有这些计算。

## 后续

本项改动的必要验证已完成。下一步按当前主体再定位热点。代码中 ViT QKV `_prepare` 仍在两个平方累加处用补偿 `_half_fma_value`，已有 `half_fma_attention` 可作为候选；它们保留 `_nan_left` 且参数是 half，但仍需核对既有 attention 验证范围、全部 8 个实际 QKV 输入与边界，并以新整帧计时决定是否采用。该方向本轮只查阅源码，尚未修改、验证或宣称收益。

完整目标仍包含精确后端更多尺寸/HDR/控制、OptiScaler/XeSS/ComfyUI 生产接口、性能持平及 INT8 路线；此次有限尺寸 FP16 优化不是完整迁移完成声明。
