# ViT64 注意力融合与主体计时（2026-09-09，本地）

当前 NR256 快速路线选用 `fused_vit_attention64_adapter_v2.py`：在原生 half cubic、dense 分块、历史和 QKV 优化之上，融合 64-token ViT 注意力。固定 NR256 输入的同轮配对测试中，完整连续调用从 12.991321 ms 降到 12.860922 ms，节省 0.130399 ms（1.0037%），三轮均变快。720 次完整 NR 输出、78 次完整残差输出、390 帧独立时序检查通过。

这是有限尺寸的 FP16 快速路线优化。输出字节与此前已获用户接受的快速路线一致，不表示与 NVIDIA 原生逐位一致。精确分支的 35 个后端文件不变。完整迁移、性能持平和生产接入仍未完成。源代码和实验记录仅保存在本地，没有发布操作。

## 本体和外围各花多久

所有下列计时的 NR 实际输入均为 256×256。当前版本的连续帧记录：

| 场景 | 主体完成时间诊断 | 完整调用 | 两次统计的近似差额 |
| --- | ---: | ---: | ---: |
| 与 4060 对齐的固定 NR256 输入 | 11.205010 ms | 12.860922 ms | 1.655912 ms |
| 1080p 画布，NR256 + 残差重建 | 10.773750 ms | 13.544752 ms | 2.771002 ms |

适合概括为：本体约 11 ms，外围约 2–3 ms，完整调用约 13–14 ms，本体约占八成。这里主体是静态捕获的 NR 主体图，包含编码器、ViT、解码器与图内前后处理，并非只有矩阵运算。

差额来自分开测量的主体诊断和完整调用统计，不是同一帧分段计时，不宜视为精确可加的 CPU/GPU 分摊。固定输入主体采用十次完成等待均值，视频主体采用五组十次重放的中位数。不同 fixture、同步方式与运行间波动会改变该差额。尤其不能把两行相减，当成缩放与合成的精确耗时。

主体以外包括动态前处理、历史采样、常量和所有权检查、调度、状态提交与完成等待；第二行还包括输入颜色/运动缩放及残差合成。这些数值不含解码、光流估计、上传、显示或游戏竞争，也不是游戏最终帧时间。

上一轮记录为本体 11.117550 / 总计 13.223358 ms，1080p 残差为本体 11.001680 / 总计 13.811118 ms。新旧不同时段数据不能直接相减归因；本次改动应以上面的同轮配对 1.0037% 收益衡量。

## 为什么尝试融合注意力

在此前 `71b0fd4` 栈上重新测量 13 个主体阶段，整段诊断为 10.889390 ms，各段之和 10.941280 ms。编码 C512 和解码 C512（含输入处理）合计约 2.151520 ms，八个 ViT 约 1.536440 ms，post 约 1.210530 ms，pre 约 0.853080 ms。所有分段完整输出及组装主体结果通过比较，阶段计时只是定位线索，段之和不是精确的整帧分解。

ViT64 原注意力需要多次独立调度。新内核在一个 tile 内保留完整计算顺序：QK 的 half 舍入、特定指数近似、指数的 FP8 边界、两个有序 K32 累加、归一化前 numerator 的 half 舍入、原始 half 分母加法树、倒数、最终 half 和 FP8。它不是标准 softmax，不能用一般 FlashAttention 公式直接替换。

内核支持独立的 Q/K/V 正 stride，避免为真实转置布局复制张量；所选配置为 BM32、4 warps、stage1。适配器只替换已拥有模型的 64×1024 ViT 输入、XPU 和 fp16_xmx/triton 模式，其他 token 尺寸或模块继续原方法。保留原逻辑 dispatch 记录，但不把融合前每个逻辑运算当作仍有独立 GPU 调度。

## V1 的限制和 V2 的验证

V1 保留旧的补偿 FMA。8 个真实 QKV 输入和 6 组零值、符号零、饱和、混合 FP8 极值及布局样例，三种 tile 共 42 组比较、252 个完整数学边界全部一致。局部八块注意力中位耗时之和从 0.177558 降至 0.112205 ms，但残差完整连续帧仅从 13.673930 降至 13.592676 ms，其中一轮回退，因此 V1 不选用。BM32 编译记录为零 spill，不能把它的弱收益归因于寄存器 spill。

V2 只将指数变换中已验证系数的补偿 half FMA 改为原生 half FMA；保留 clamp、NaN 位处理和指数位变换，不改通用 FMA。枚举全部 65,536 个 half 输入编码，V2 指数输出与原实现字节一致。保存的 LLVM IR 确认存在 `llvm.fma.f16`。完整注意力的 42 组候选和 252 个边界比较、生产输出与 debug 输出、捕获输出及输入不变检查均通过。全 half 枚举针对指数函数，不是任意非有限 Q/K/V 的整个注意力完备证明。

V2 同轮局部八块之和：原方法 0.175428 ms，V1 融合 0.112252 ms，V2 BM16 / BM32 / BM64 为 0.094125 / 0.088913 / 0.109202 ms。局部收益不能等比例套到整个主体。

在实际模型适配器上，再比较 8 个 ViT 块的七个完整边界，及零值、非连续特征、FP32 特征、96-token 回退、非所属模块回退共 5 组检查。所有边界一致，图构建逻辑计数、前后 K8、83 次 dense 分块和原生 cubic 调用保留。

## 完整流程性能与正确性

| 同轮配对范围 | 上一版 | V2 |
| --- | ---: | ---: |
| 固定 NR256，连续帧完整调用 | 12.991321 ms | 12.860922 ms |
| 固定 NR256，重置帧完整调用 | 12.757669 ms | 12.548968 ms |
| NR256 + 1080p 残差，连续帧 | 13.652864 ms | 13.544752 ms |
| NR256 + 1080p 残差，含重置 | 13.628887 ms | 13.501408 ms |

固定输入连续帧三轮，上一版 12.920302 / 12.948317 / 13.105345 ms，V2 12.754600 / 12.889970 / 12.938195 ms。残差三轮有一轮略慢（13.629573 -> 13.656009 ms），因此不能声称各场景均有稳定 1% 收益。选择 V2 的依据是主要目标固定 NR 完整调用的三轮均获益，以及全部正确性检查通过。

4060 相同 NR256 完整主机调用参考为 3.566807 ms，当前 B580 约为其 3.605724 倍，尚未持平。不使用 480p 或 1080p 原生速度计算这个比值，也不使用主体 GPU 事件区间代替完整调用。

720 次固定输入完整结果同时匹配同轮基线和冻结 3.7.2 快速结果。78 次残差测试检查低 NR 与完整 1080p 输出、历史、seed、调用方所有权、保留输出、非法运动拒绝和 LUT 身份/版本。390 帧采用独立不中断的历史，全部低 NR 字节及完整 FP32 合成哈希匹配已人工审核视频，重置复现首帧。未重新编码视频或另存大帧副本；依照用户的字节一致豁免无需新增肉眼审核。

图构建阶段的 48 次 ViT 注意力调用对应六次主体执行，后续由图重放执行，不代表整个视频只有 48 次计算。所有测试沿用串行 GPU lease 与隔离 Triton 3.8，未改动全局工具链。
