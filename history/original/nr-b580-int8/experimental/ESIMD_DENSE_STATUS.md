# ESIMD DPAS 布局实验与舍入定位

2026-09-09。继 `BLACKWOOD_XPU_REVIEW.md` 后的本地实验。结论：博客中的操作数预排方法在 B580 的部分 NR 矩阵上有实测价值；还没有接入完整模型，当前运行时仍为 fee6d0d 的 WindowBlocks v3 栈。精确分支与公开仓库均未修改，没有发布。

## 已实现与验证

独立 oneAPI 2026.1 SYCL/ESIMD DLL，AOT 编译为 BMG，在 PyTorch 当前的有序 Level Zero 队列异步提交。没有安装作者扩展或更换 Torch。每个 ESIMD work-item 计算 8×16，沿 K16 执行 FP16 输入、FP32 累加的 `dpas.8x8`。静态 B 预排为 VNNI；比较原始 A 直接读取、预排 A 的纯计算，以及逐次 GPU 重排 A 加计算三条路线。

两种加载内核在提交前均查询并通过零 spill 检查。实际加载模块的机器码确认使用 FP16 DPAS；`.ze_info` 的 GRF 配置为 128。SYCL 查询同时返回原始 `ext_codeplay_num_regs=10`，其口径没有厘清，不能将它解释为只用 10 个 GRF 或据此推导占用率。

v3、v4 各验证了 32 组真实捕获矩阵，代表捕获表中的 163 次调用；原捕获有 34 组、167 次调用，另两组因非连续布局未覆盖。这些来自之前的真实 NR 捕获，并非新一次完整模型运行。两版所有已测真实输出均与已审核快速分支逐字节一致。每条路线还验证了 XPUGraph 在输入清零后输出变化、恢复输入后恢复原输出，排除了仅重放旧输出复制的情况。输入没有被修改。

图内每批四次矩阵调用，五轮交错顺序，每轮十五次图重放，主机计时包含完成等待；最后一次输出复制也在图内。预排权重只在准备阶段计算。`esimd_with_pack` 每次都包含动态激活重排，`esimd_prepacked_only` 不能当作完整层耗时。下表为 v3 同次配对结果：

| M×K×N | 初值 | Triton / ms | ESIMD 含动态重排 / ms | 耗时变化 |
| --- | --- | ---: | ---: | ---: |
| 144×512×512 | 无 | 0.011037 | 0.007677 | −30.4% |
| 144×512×512 | 有 | 0.011618 | 0.008362 | −28.0% |
| 64×512×1024 | 无 | 0.014065 | 0.007848 | −44.2% |

## 查清的数值陷阱

v3（C++ 源码 v3、build v4）在随机 FP16 的 9×32×32 用例中有一个 half 不同：位置 [1,27]，原 Triton 为 2.181640625，ESIMD 为 2.1796875。原始 A、B、initial、完整输出均保存，可重现。不能凭真实捕获通过就称为通用 FP16 等价替换。

最初插入 FP32 累加值输出的 Triton 探针也改变了最终 half，v1 检查因此失败。v2 保留这一事实，并通过活着的 PyTorch/Triton SYCL kernel bundle 取得实际加载的 Level Zero 原生模块。机器码给出具体解释：

- 原 9×32×32 `_matmul` 将 initial 转为 FP32，作为第一条 DPAS 的累加输入，没有保留源码末尾的独立加法。
- 同形状插桩版本从零累加，在末尾执行 FP32 加法。它与 ESIMD 的完整 FP32 累加值和 half 输出一致，BK16/BK32 在这三个探针用例上也一致。
- 原 31×128×64 `_matmul` 则从零 DPAS 累加，末尾另加 initial。因此不能简单规定所有形状都先加 initial。

在差异点，后加路径保存的点积为 1.8698731660842896，加初值后 FP32 为 2.1806640625，正处于 half 舍入中点。输入的 FP64 数学和为 2.180664162267931。证据支持“编译器对初值加法的重排导致此次差异”，不支持“ESIMD 数据排错”或“只要固定 K32 就保证相同”。

v4（C++ 源码 v4、build v5）改为先放 initial：修复 9×32×32，却在扩展随机测试的 K128、K2048 用例出现差异。其 32 组真实捕获仍全字节相同，但通用替换门槛依然未通过。两版都没有晋升为运行时。

## 冻结证据与版本

代码位于此目录，实验数据和编译产物全部在 `D:/Codex-NR-Experiments/nr-b580/reference/experimental`。

| 实验 | 结果 |
| --- | --- |
| build v1 / C++ v1 | 编译失败：当前 API 是 `esimd::xmx::dpas`，并需修正编译标志/ocloc PATH |

## 下一步选择

先做无 initial 的深层矩阵，以及直接产生 DPAS 布局的上游融合，降低重复读取、重排与发射成本。带 initial 的兼容性需要显式区分固定编译产物的实际算术顺序，不能按 K 值猜测。任何正式接入仍需当前 WindowBlocks v3 的完整 NR256、残差、时序和所有权验证，再决定保留。若改变已审核输出，按用户要求提供完整对照视频。

作者资料中，博客与 A770 优化记录对本轮最直接；omni 的 oneDNN INT8 与 Aila 可参考融合和生命周期，但不能从整数输入推断纯整数执行；InferRef 对记录参考复刻过程有价值。详细固定来源链接见 `BLACKWOOD_XPU_REVIEW.md`。上述部分矩阵收益仍不足以宣称已经接近 4060，也没有新的整帧成绩。
