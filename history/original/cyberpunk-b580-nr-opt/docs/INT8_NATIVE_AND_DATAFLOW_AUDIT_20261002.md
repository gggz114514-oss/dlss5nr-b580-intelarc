# INT8 原生矩阵与完整数据流审计

开发基线仅为《赛博朋克》现役 720p C512＋K8。精确 4060 分支不改，旧 C32/C128/C256/C512 实验仅作为原因线索，不视为当前游戏速度结论。当前安装仍是用户验收画面、真实运动、焦点切换正常、RTSS 55–60 ms/帧的桥组合；本审计没有替换游戏文件。

## 审计应区分的三类问题

1. **4060 数值对齐遗留**：实际执行的 FP8 舍入、补偿运算、逐段低精度累加等。依据实际 constexpr、调用者和已加载编译 key 判断；导入、函数名或记账标签不代表执行。
2. **B580 上的实现组织**：矩阵虽然用 XMX，仍可能重复读输入、tile 过小、分支串行、寄存器溢出、布局交换低效。采用了硬件矩阵指令不等于有效吞吐已高。
3. **相邻算子与表示边界**：量化入口、激活、INT32 重缩放、临时张量、残差读者和下游是否直接消费。必须与完整 FP16 模块比较，不能仅以一个矩阵核的时间决定取舍。

之前仅以“能运行／用了 XMX／关了舍入”判断原生化是否完成，覆盖不够。当前注意力核已经是 FP16 DPAS；换成另一份同 tile、同布局、同数学量的 FP16 核没有确认整图收益，不能反推 Triton 多了一层 GPU 运行时解释。INT8 则需要核对整数指令以及其周围仍然保留的工作。

## C128 源码已找到的具体成本

旧整数 `_pairs` 按 4 个 32 列输出部分运行，每一部分重新加载 X。现役 FP16 `_pairs_pairwise` 把相邻两部分放在同一 K 循环中共享 X，只循环两次。对同一个 96×160×128 输入、4 分支的静态逻辑请求，整数为 `M×C×4分支×4次×1字节`，FP16 为 `M×C×4分支×2次×2字节`，二者均为 **30 MiB**。这不是测得的显存流量：编译器、L1/L2 和其它复用会影响实际访问。它表明整数数据减半可能被当前重复读取抵消；值得改写的是读取组织，不是仅改输入 dtype。

旧整数激活 LUT 是每通道 256 档的 INT8 cubic 激活表，4×128×256＝128 KiB。其数值来自 cubic 多项式的整数标定；**不是 FP8 编码表或 4060 舍入表**。Q12 使用 INT32 把累计结果重缩放到下一 INT8 范围，也不是模拟 FP16/FP8。直接删掉二者会改变必要的激活／尺度运算，不能叫作清理 4060 遗留。

旧局部删 LUT 的诊断摘要中，中位时间 0.287995→0.2247135 ms，继续删 Q12 为 0.210807 ms。两个 dot 序列保留，说明矩阵周围的工作值得查；这些只有摘要、没有 raw samples，且输出语义已变，不能作为可部署候选或可相加的预算。

旧 QKV 已直接读取投影产生的 INT8 QMLP，没有先反量化再量化。同一投影同时输出 FP16 residual，供该 block 的残差读者使用；这是浮点边界，但不能误说整个下游都只接受 FP16。QKV 后的 Q/K 归一化和窗口排布保留浮点；实际 `ROUND_QKV=False`，源码存在 `_round_fp8_half` 不代表这次执行了它。

旧 tile 摘要中，INT8 16×1 改 32×1 的组 P50 均值约 0.288906→0.223646 ms，改善明显但仍慢于当时 FP16 pair 的 0.164140 ms；32×2 未更好。改变 tile 已能影响实现效率，但旧 FP16 不等于现役 pairwise＋FP32 projection，单次 Event 也可能包含 host 提交空档。

## 本轮新测量与判别

仅在隔离 artifact 开发，不装入游戏。来源固定为现役 C512＋K8、ref4＋probability＋C128/V6 导出的真实中间张量和 owned 权重：`native-math-fixture-export-v1-20261001/export-02/mlp-fixture.json` 中的 `encoder128.0`。现役完整 FP16 对照为 `_pairs_pairwise`＋`_project_fp32`，保持当前 `num_branch_c128` 数值策略。整数使用独立标定的 Q12/LUT 语义，不要求匹配 FP16 字节；对整数 CPU 参考要求一致，并记录相对 FP16 的误差。

所有权重、输入、中间与输出先分配，标定和编译放在计时外。比较普通 Event 与每图至少 16 次完整模块的图重放，原始 B-C-C-B 每组 50 样本。分开测含入口的完整 INT8 模块、预量化 INT8 核链、入口、pair、projection；partial 数据明确标识，独立阶段不相加冒充完整成本。记录实际加载 key、INT8/FP16 dot 类型、spill 与只读缓存命中。

判别顺序：若图内预量化核链仍慢，优先查 pair 输入共享、激活／重缩放、tile、布局及矩阵占用；若核链快而完整模块慢，优先改生产者直接给 INT8、融合量化入口、残差及下游双输出布局；若普通提交慢而图内有效，优先修 host 提交／capture 覆盖。尚不能预支其中任何结论或整帧加速。

CPU 由主任务审查，GPU 仅由 Luna 获得独占 GO 后串行执行。没有 1 ms 淘汰门；有可重复净收益才安排整帧与用户画面审核，画质差异记录后由用户判断。

## 本轮真实中间张量测试已完成

Luna 执行 `int8-c128-cost-graph-v2-20261002/probe-01`：fresh-cache prepare 与独立只读 measure 子进程均 exit 0，10 个实际 key 与加载二进制一致；全部 32 行都先毒化输出，再用图重放恢复完整 eager SHA、核对输入未改变，之后才采集普通 Event 与 graph16 的各 50 个原始样本。主任务仅用标准库重算并核对：[原始数据独立复核](D:/Codex-NR-Experiments/cyberpunk-opt/int8-c128-cost-graph-v2-20261002/probe-01/MAIN_GRAPH_RAW_REVIEW.json)，SHA `d4375867732576fc25b1a1a2bb241db9b0a91899025811857daa1c1e7b311512`。

| INT8 入口＋pair＋投影／FP16 residual 出口 | 0.327230 | 0.239710 |

| 裸 INT8 单分支 expand：INT32 输出 | 0.020227 | 0.017543 |

BM32 完整 INT8 比现役 FP16 慢约 **0.1403 ms／2.41 倍**；去掉入口后仍为 0.2333 ms，差距没有消失。与本轮普通提交相比，图重放使裸矩阵计时中的 host 空档明显缩小；BM32 裸 INT8 expand 比 FP16 快约 **13.0%**，但这是没有激活／reduce／project 的诊断，不能当作完整 INT8 方案或整个网络的收益。

目前可以确认：**这一旧整数 MLP 的主要失利发生在模块内部，入口转换不足以解释；实际矩阵路径已有 INT8 DPAS。** 核心并非在用 FP16 模拟整数。pair 内四次重读输入、每通道 cubic 查表、Q12 重缩放及不同矩阵组织需分别改写和验证；本次没有把这几项各自耗时完全分离，不能全部归给查表或全部归给搬运。projection 诊断仍包含必要重缩放与浮点 residual 出口，也未分离成纯转换时间。各分段 P50 不能相加当作完整模块成本。

32 行稀疏独立整数 CPU 参考、未裁剪整数总和的 FP16 出口、重复输出和有限值检查均通过。两个整数 tile 数值一致；相对现役 FP16 的完整张量误差为 MAE **0.1021285**、RMS **0.1581487**、最大绝对误差 **1.1953125**。它们是中间激活误差，不是最终 RGB／PSNR／用户画质结论；本轮没有输出视频或改变游戏安装。

实际加载的 pair／project／bare 内核 IR 均有相应 FP16 或 INT8 的 Intel 矩阵 intrinsic，运行时资源记录 spill=0。零 spill 不证明占用高效，未取得最终硬件 ISA 或物理 ALU／DRAM 周期。BM32 FP16 B1→B2 P50 漂移仅 −0.000386 ms，INT8 C1→C2 为 +0.001833 ms；明显的完整模块差距不靠选择单轮较快样本成立。

下一步遵循统一现役审计：先优化已能证明执行的内部组织，整数候选保持 cubic 激活和量化尺度的有效语义；改写后再测完整模块与整图。不能把这一次 C128 的失利套到其它 C／不同布局，也不能把裸矩阵的小优势许诺成整帧速度。
