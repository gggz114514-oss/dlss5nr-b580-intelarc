# 《村庄》游戏帧时间与 NR 面板读数的差额

2026-09-27，用户在厨房实机场景的截图中看到 RTSS/游戏叠层约 **42.8 ms/帧、23 fps**，同屏网页 NR 面板约 **30.27 ms/帧、估算 33.0 帧/秒**，相减约 **12.5 ms**。该差额**不能标为“桥额外耗时”**：游戏帧时间包含原有渲染、XeSS、呈现、调度及 NR；面板处理时间覆盖 NR 输入准备、推理、合成与 GPU 等待，两个数字的边界与时钟均不同，工作还可能重叠。截图显示模型输入为 360p、融合历史、图重放、模型强度 1.0，游戏分辨率/场景状态与离线基准不可直接横比。

为核对“NR 开关究竟增加多少游戏帧时间”，在用户保持厨房镜头不动时，使用本机 RTSS SDK 定义的只读共享内存 `dwFrameTime`（微秒）记录同一进程四段短窗：NR 开／关／开／关，每段切换后等待 1.5 秒，再以约 20 Hz 采样 4 秒、80 个观测点。只切网页的 `enabled`，保留 360p、风格、历史、图重放及 XeSS 设置，最后恢复 NR 开启。工具：[只读采样与开关脚本](../tools/measure_re8_nr_increment_v1.py)；原始记录：[RTSS 四段报告](D:/Codex-NR-Experiments/nr-b580/re8-bridge-frame-gap-20260927/rtss-on-off.json)。

| 360p 厨房静止镜头 | 第一段中位 / P95 | 第二段中位 / P95 | 两段中位平均 |
| --- | ---: | ---: | ---: |
| NR 开 | 42.338 / 43.07 ms | 42.280 / 43.15 ms | **42.309 ms** |
| NR 关、桥 DLL 仍加载 | 16.689 / 17.95 ms | 16.7065 / 17.85 ms | **16.6978 ms** |

同场景的**整条 NR 开启路径净增帧时间**约 **25.61 ms**，不是 12.5 ms。NR 开启两段的面板平均处理时间约 30.20/30.21 ms。`16.70 + 30.20` 不能作为严格逐项求和式与 42.31 ms 比较；两个计时范围可能重叠，面板包含 GPU 等待，且 RTSS 读数是采样窗口而非每帧完整追踪。此结果足以否定“42.8−30.27≈12.5 ms 就是桥自身代价”，但**尚未单独测出桥的固定开销**。要测它，需同配置对比桥 DLL 加载但 NR 关闭与完全不加载桥，或在同一链路内插入可比的阶段标记；当前 16.70 ms 仍包含加载但关闭的桥。

局限：静止场景、短窗、RTSS 约 20 Hz 抽样，未测输入到显示的端到端延迟，也未跑运动场景分布；数字不可当作其他游戏或 480/540p 的固定税。采样后面板已恢复 `enabled=true`、360p，健康状态正常。
