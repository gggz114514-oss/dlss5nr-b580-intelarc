## §1 落地内容

`backend/nr_backend/sampling.py` **两棵树同改**：

| | 值 |
|---|---|
| sha256（改前） | `fb13d07cdc0b0fe7636c210711f84d5f996102dd68762b10193602cc93b08b56` |
| sha256（改后，两棵树同值） | **`1b6b26c7515c8eca5ead67c34f274df0dd79f345a1fcdc5d7080161a7cbc18c3`** |
| 行数 | 204 → **231** |
| 开关 | **`NR_MOTION_SCOPE`**（默认 `on`）＋ **`NR_MOTION_SCOPE_TOL`**（默认 `1/256`） |
| 备份 | `backup/sampling_nr_b580_orig.py`、`backup/sampling_nr_b580_int8_orig.py`（两份都是 `fb13d07c…`） |

**改的是什么**：`_sample_five_axes` 是 `_half_texture_counts` 的最内层采样器 —— 5 次双线性抽头
（每抽头一次 `reciprocal`）＋ 权重合成。`N2b` 只短路了**恰好整数 motion**那一支，上游 5 次
`sample()` ＋ 权重 ＋ 每像素 `reciprocal` 仍在跑。本刀把「六个轴项全部落在采样器自身
1/256 像素定点栅格内」这一支整体短路到中心抽头：

```python
if _MOTION_SCOPE_ON and bool(((x0.abs()<=TOL)&(x3.abs()<=TOL)&((gx-1).abs()<=TOL)
                             &(y0.abs()<=TOL)&(y3.abs()<=TOL)&((gy-1).abs()<=TOL)).all()):
    value = <只取 coordinates[2] 一次采样>
    ones  = torch.ones_like(gx)          # total == 1 ⇒ reciprocal 用 1.0 代替
    return value * ones[..., None]
```

**⚠️ 这不是逐位恒等**：邻居抽头仍带 ~1.7e-05 权重，且 `total` 被当作恰好 1 ⇒ 输出动 O(1e-5)。
所以它走的是「送审 → 人工审核 PASS → 落地」那条路（2026-09-19 18:52 用户裁「画面 PASS」）。

**落地体与外挂刀逐字同形**（`motion_scope_v1/motion_scope_cuts_v1.py:184-256`）—— 同一套六个门控项、
同一个 `ones = ones_like(gx)` 替代 `reciprocal`、同一个 `value * ones[..., None]` 返回式。
这是"落地 == 送审"的第一层论证；第二层是 §4 的实测。

**派生记录**：`D:/motion-scope-land-v1/exact-derived/validation.json`
（sha `4fff2ee0e9cdc5e07afd1bc7de754cf52b73048b41422529621cc67f98498a58`）。
链条每份只推进 `sampling.py` 一项：锚点 → `warpsync-land` → `allmerge-land` → **本轮**。
脚本逐项断言 243 个输入帧的 `sha256` 与磁盘一致、`loaded_sources` 里**恰好一项**变化
（就是 `sampling.py`），否则报错退出。

## §2 证据一：CPU 预检（不占卡）— **ALL PASS**

`motion_scope_land_cpu_check_v1.py` → `cpu_check.json`：

| 检查 | 结果 |
|---|---|
| 两棵树 `backend/nr_backend` 逐字节一致 | **35/35** |
| 两份备份 sha | 都是 `fb13d07c…` |
| `on` 默认读到 | `flag=True`、`tol=0.00390625`（= 1/256） |
| `off` 默认读到 | `flag=False` |
| 两个模式是**不同**的模块对象 | ✔（`importlib.reload` 会就地改同一个对象 —— 踩过） |
| `off` ≡ 备份原函数 | **逐位相同**（`max_abs=0.0`） |
| `on` ≡ 单点 oracle（门开火时） | **逐位相同**（`max_abs=0.0`） |
| ★ **`on` ≠ `off`**（本刀**不是**逐位恒等） | `max_abs = 5.037e-05` > 0（写成**会 FAIL 的断言**） |
| tol 对照：1/256 → 不同；tol=0 → 逐位相同 | `5.037e-05` vs `0.0` ⇒ **门确实是开关** |

**★ 一条本轮新学到的真事实**：**恰好**整数 motion 在 **CPU** 上残差为 **0**（`fma32` 走 double）
⇒ `on ≡ off` 逐位相同。要复现"会改画面"的形态，必须**手工注入 XPU 残差量级**
（`2.5749e-05`）。否则 CPU 预检会给出"这把刀什么都没干"的假结论。

## §5 证据四：速度 —— 配对省 **+1.6995 ms**（4/4 同号）

四轮 ABBA（每轮 8 臂 = `off on on off | off on on off`，同 session、位置对称，12 帧/臂、
稳态取 `frames[4:]` 中位）：

| 轮 | `off` 均（4 臂） | `on` 均（4 臂） | **Δ** |
|---|---:|---:|---:|
| r1 | 50.1740 | 48.2665 | **+1.9074** |
| r2 | 50.0873 | 48.6210 | **+1.4663** |
| r3 | 50.2537 | 48.4286 | **+1.8251** |
| r4 | 49.9300 | 48.3308 | **+1.5992** |
| **配对均值** | **50.1112** | **48.4117** | **+1.6995 ms** |

**同变体 spread**：`off` n=16 spread **1.1472**（2.29%）｜`on` n=16 spread **1.0930**（2.26%）
—— **没有离群臂**。

**判据（技能 127）**：

* 符号一致 **4/4**；
* Δ = 1.6995 **>** spread(off) = 1.1472 ✓
* Δ = 1.6995 **>** spread(on) = 1.0930 ✓
* ⇒ **保守判据（对较大的那个 spread）通过 ⇒ 可判。**

**池化统计量**：

| 批次 | n | mean | sd | t | 95% CI | 判 |
|---|---:|---:|---:|---:|---|---|
| 外挂轮（送审那一版） | 3 | +1.6830 | 0.3346 | 8.71 | [+0.8517, +2.5143] | 可判 |
| **落地轮（现行产品）** | **4** | **+1.6995** | **0.2028** | **16.76** | **[+1.3768, +2.0222]** | **可判** |
| **池化两批次** | **7** | **+1.6924** | **0.2408** | **18.60** | **[+1.4697, +1.9151]** | **可判** |

**⇒ 落地轮的 CI 更窄（宽 0.65 ms vs 外挂轮 1.66 ms）、t 更高（16.76 vs 8.71）、且无离群臂。**
族间 sd 比 **1.65×**（0.3346 / 0.2028）—— 按技能 139，两个都报，不挑。

**口径**：`off = 50.1112 / on = 48.4117` ⇒ **−3.39%**。折算 **19.956 → 20.656 fps**（折算，非测量）。

### 5.1 一条独立的产品侧旁证

`fastpath.json`（每臂的 `[prod]` 自证）里，两臂**只有一处不同**：

| 字段 | `off` | `on` | 差 |
|---|---:|---:|---:|
| `launch.stats`（hits / misses / verify_fail） | 232151 / 414 / 0 | 232151 / 414 / 0 | **相同** |
| `select`（calls / hits / misses / verify_fail） | 45927 / 45889 / 38 / 0 | 45927 / 45889 / 38 / 0 | **相同** |
| **`scalar.hits`（FMA scalar cache）** | **7737** | **3865** | **−3872** |

两臂 `launch` / `select` **逐字相同** ⇒ 跑的是**同一批帧、同一套图**（顺带否掉"两臂输入不同"的怀疑）；
而 `scalar.hits` 少了 **3872 次**（243 帧 ≈ 15.9 次/帧）—— 那正是短路省掉的每像素 `reciprocal`
查表。**这是"短路真的在产品里生效"的第三个独立观测**（前两个：`gate_probe` 的 `flag`、
`on` 臂的非逐字节）。

## §6 与外挂轮的对照（**复现，且证据更强**）

| | 外挂轮（送审那一版） | **落地轮（现行产品）** |
|---|---|---|
| 装置 | 外挂刀 `MOTION_SCOPE_CUTS=fiveaxes` | **产品源码 + `NR_MOTION_SCOPE=on`** |
| Δ | +1.683 ms | **+1.6995 ms（101%）** |
| 符号一致 | 3/3 | **4/4** |
| 95% CI | [+0.852, +2.514] | **[+1.377, +2.022]** |
| `\|Δ\| > spread(off)` | ✓（1.1034） | ✓（1.1472） |
| `\|Δ\| > spread(on)` | ✗（含离群臂 2.4265）**未达严格判据** | ✓（1.0930，**无离群臂**） |

**⇒ 外挂轮记录值 `+1.683` 落在落地轮 CI 内 ⇒ 复现。**
而且落地轮**不需要"剔除离群臂"这一步**就通过了保守判据 —— 外挂轮当初卡在那一格。

**为什么这一轮能复现而 `allmerge` 那一轮不能**（诚实归因，不做过头解释）：
`allmerge` 省的是**归约 + device→host 回读**，而当前帧是 **host 受限**（host/device = 1.19×）
⇒ 设备侧的小节省**大部分被既有的 host/device 重叠吸收**，效应被压到噪声量级。
本刀省的是**每像素的 4 次采样 + 1 次 `reciprocal`**，落在 **host 侧**（Python/派发），
正好是瓶颈侧 ⇒ 效应量级大 10 倍且稳。**同一个道理反过来也解释了为什么它是 10 倍**。

## §7 口径与边界（不许沉默）

1. **`+1.6995` 不与历史轮次的绝对毫秒相加**。跨轮/跨 session 的绝对毫秒一律不可比
   ⇒ 它**不并入**帧墙链 `82.2 → 64.82 → 57.88 → 51.96 → 50.54 ms`。若只按量级折算，
   现行帧墙约 `50.54 − 1.70 = 48.84 ms` —— **这是折算，不是测量**。
2. **帧率 20.656 fps 是折算**（1000 / 48.4117），不是测量。实时门（XeSS-FG 输入 40/60 fps
   ⇒ 25.0/16.7 ms）**仍未达成**：48.84 ms ≫ 25.0 ms。
3. **本轮的绝对毫秒与上一轮不同口径**：上一轮 `allmerge` 落地后的臂中位是 50.10（非交替全量臂），
   本轮 ABBA 的 `off` 均 50.11 —— 数值接近是巧合（不同入口、不同帧序），**不要拿来互证**。
4. **未测**：`car` 1920×1080 素材（该素材是 1080p、390 帧；`rows_entry_v1.py:146/:387` 硬锁 480×864）。
5. **本刀的画面变化已被人工审核接受**，但审核是在**送审素材**上做的；§4 论证了落地形态与送审候选同一
   ⇒ 审核结论对落地形态有效。**若日后有人改动 `NR_MOTION_SCOPE_TOL`，这个论证立刻作废**
   （tol 变了就是另一把刀，必须重新送审）。
6. **`off` 分支不是"安全回退开关"**：`NR_MOTION_SCOPE=off` 只保证**逐字节回到落地前**，
   它**不**是一个"画质更好"的选项 —— 它跑的是同一套五抽头，只是慢 1.70 ms。
