## 2. 改了什么

`fused_qkv_pack_native_half_v1.forward()`（原 79 行）：

```python
# 改前
q, k, v = [torch.empty(shape, dtype=z.dtype, device=z.device) for _ in range(3)]
# 改后
q, k, v = _scratch(shape, z.dtype, z.device)
```

`_scratch` 按 `(shape, dtype, device)` 缓存这一组三块工作区，**追加在文件末尾**（第 88 行，
在 `forward`(66) 与内核(17) **之后** ⇒ 内核起始行号不动，技能 146）。
`NR_QKVCACHE=off` 时走 `torch.empty` 三连，逐字复现落地前。

### 2.1 等价性依据（比刀 A 更硬）

`_pack` 对 Q/K/V **只 `tl.store`、从不 `tl.load`**（`fused_qkv_pack_native_half_v1.py:58-63`）：

```python
output = tl.where(family == 0, Q, tl.where(family == 1, K, V))
dest = r[:, None] * 32 + lane[None, :]
tl.store(output + dest,      _round_fp8_half(x0), valid)   # +0/+8/+16/+24 ⇒ 恰好每行 32 个
```

* `dest` 覆盖 `r*32 + 0..31`，而缓冲共 `COUNT*32` 个元素、`COUNT = h*w*heads`；
* `r` 由 `grid = cdiv(h*w*heads, rows)` 覆盖 `≥ COUNT`，越界行由 `valid = r < COUNT` 屏蔽；
* ⇒ **每次调用把三块缓冲整块无条件重写，与旧内容无关。**

★ 刀 A 靠"pad 是空操作"，本刀靠"**输出缓冲是只写的**" —— 后者不依赖参数、更强。
（这不是推断：`243/243` 的配对门就是它的实证。）

### 2.2 别名风险（本刀唯一的真风险）—— 已静态审计 + 实证

跨调用复用 = 两帧共享同一块显存。审计（`qkvcache_land_alias_audit_v1.py`，**纯静态、零租约**）：

| 判据 | 结果 |
|---|---|
| 全仓 `import` 该模块的文件集合 | 恰好 9 个，全部可枚举；**exact 树 0 个**（本刀只改 int8） |
| 产品调用点 | **只有 2 个**：`window_blocks_v3.py:30`、`native_half_head_layout_v1.py:33` |
| 两处是否就地消费 | 都是 `(q,k,v),_ = prepare(...)` 后**同作用域内立刻**交给 `attend`/`forward`，**不跨帧持有** |
| 返回值是否别名 q/k/v | `attend` 返回 `out = torch.empty_like(query)`（**新张量**）；`selection` 是**纯 dict**（`dict(selected=…, attempts=…)`，不含张量）；`kernel` 两处都丢弃 |
| `spill_preflight_v1._signature` 的缓存键 | 张量只贡献 **`(dtype, data_ptr() & 15)`** —— **16 字节对齐，不是地址** ⇒ 复用缓冲**不会**造成错误的 kernel 选择命中 |
| 产品路径是否多流 | **没有**（`torch.xpu.Stream()` 只出现在 `benchmark_*`）⇒ 跨帧复用受**流序**保证 |
| 流序 | `_pack`(写) → `_kernel`(读) → 下一帧 `_pack`(写)，同流串行 |

**残余风险**：同帧内若有两处同时持有同一 shape 的工作区，会互相覆盖。**由配对门实证排除**（243/243）。

> **★ 2026-09-20 守卫修正（技能 173，来自刀 C 轮）**：本审计的判据「exact 树不得 import 本模块」
> 有一个**扫描域缺陷** —— 扫描根是 `nr-b580/`，而 `nr-b580/reference/` 是**装置/轮次根**、
> **不是产品路径** ⇒ 本轮的入口脚本 `reference/<round>/…_entry_v1.py`（它当然要 import 产品模块）
> 会被算成**产品调用点** ⇒ **假红**。
> **本审计在第一次运行时没有暴露这个 bug，只因为那时刀 C 的入口脚本还没写出来。**
> 已修：`files_importing()` 增加 `if rel.startswith('reference/'): continue`（与 `/backup/` 并列）。
> **修后复跑：`✓ 审计通过`，exit 0。**
> ⇒ **可复用规则**：**守卫的扫描域必须先确认「装置根」在哪一层**；
> 凡是"扫描全树"的静态判据，都要先问"**我自己住在哪**"。

## 3. ★★ 本轮最大的方法发现：**预热是「整臂」级别的，不是「臂内前几帧」**

r3（16 臂、**没有**预热块）暴露的问题：

| 臂 | 0 | 1 | 2 | 3 | 4…15 |
|---|---|---|---|---|---|
| 中位 ms | **54.43** | **50.99** | **47.20** | 47.47 | 46.4–47.9（逐帧 ±1） |

臂 0/1/2 的逐帧序列**剧烈抖动**（臂 0：78.3, 43.7, 43.9, 51.6, 57.8, 48.2, 54.7, 63.5, …），
臂 3 起才稳定。而 ABBA 的 `off on on off` 把**最差的臂 0 放在 `off` 位**
⇒ **系统性偏向「on 更快」**。

### 3.1 修法：预先声明的**预热块**

正式臂之前先跑**一个完整的 ABBA 块**并丢弃。ABBA 的**分块**特性使这个操作**免费且无偏**：
块内 `off on on off` 自身平衡 ⇒ **丢整块不破坏 off/on 平衡**。

工程细节：预热臂目录名用**下划线**（`warm0_off`）而不是连字符 ⇒
分析侧按 `-` 拆 tag 时**自动排除**，不需要在分析脚本里写任何"忽略名单"。

### 3.2 验证：**事后**数与**预先声明**数独立吻合

| 口径 | 配对中位 | 池化均值 | 95% CI | 判定 |
|---|---|---|---|---|
| r3 全部 16 臂 | −0.8943 | −0.3628 | [−1.3448, **+0.6631**] | **跨 0，解不出** |
| r3 **事后**丢首块（12 臂） | −0.4380 | −0.7086 | [−1.2139, −0.2807] | 不含 0 |
| **r4 预先声明预热块 + 16 臂** | **−0.7303** | **−0.7569** | **[−1.1392, −0.3913]** | **不含 0** |

⇒ r3 的"事后"数（−0.7086）与 r4 的"预先声明"数（−0.7569）**独立吻合**
⇒ **规则本身被验证**，不是挑数。**本刀结论取 r4。**

### 3.3 回查刀 A：结论站得住

`padguard-land-v1/r7` 的臂中位**全部**在 46.5–47.9（**没有预热污染**，因为 r7 跑在 r1–r6 之后、机器已热）：

| 口径 | 配对中位 | 池化均值 | 95% CI |
|---|---|---|---|
| 全部 16 臂 | −0.4255 | −1.0198 | [−2.1783, −0.2415] |
| 丢首块（12 臂） | −0.5067 | −0.9006 | [−1.9351, −0.2613] |

⇒ 两种口径**都排除 0**，**刀 A 的结论不变**，无需重跑。

## 6. 诚实边界

1. **`submit_all_ms` 本轮仍然拿不到**（那是普查轮补丁加的键；落地轮 harness 没有）
   ⇒ "省在 host 侧"仍是**机制推断**（156 次分配消失是实测，但它折算成 host 毫秒是推断）。
2. **绝对帧墙（off 46.61 / on 46.14）跨 harness 不可比**，只报配对 Δ。
3. **预热块的"必要性"未被独立证明**：r3 暴露了失效模式，r4 因为机器已被 r3 捂热而**没有**再暴露
   ⇒ 保留它是**廉价保险**，不能说"r4 证明了它必要"。
4. **`experimental/*` 不在受保护源清单里** ⇒ 本刀**不需要派生记录**。
   但这也意味着：**`exact` 树的运行不会走到这段代码**（该文件只在 int8 树），
   所以本刀**对精确线的影响为零**（不是"很小"，是路径上不存在）。
5. **缓存常驻 42 块 ≈ 数十 MB**：14 个形状里最大 `(2,17,29,64,32)` ≈ 3.9 MB/块
   ⇒ 常驻约 **50 MB 量级**（未精确统计）。这是**用显存换 host 时间**，方向与本刀目标一致。
6. **帧级实测 0.7569 ms 是微基准预测 0.2835 ms 的 2.67 倍**（156 × 1.817 µs）
   ⇒ 符合技能 149「孤立调用价是**下界**」；本刀比值比刀 A（2.3×）更大，
   因为省掉的不只是分配器查找，还有**每次三连分配的 Python 层循环与三次入队**。
7. **r3 的 16 臂数据仍然保留**（`D:/qkvcache-land-v1/r3`），作为"没有预热块会怎样"的现场证据。
