# 真纯 INT8 模块筛选（2026-09-23）

目标是分清整数计算本身与 FP16↔INT8 边界的耗时，避免把“INT8 慢”一概归因于转格式。所有数值来自同一段冻结 480p 人脸素材的 B580 单模块捕获，不是完整视频的配对帧时间；CPU/GPU 整数码逐阶段字节一致只证明候选实现正确执行自身定义的整数算术，不证明画质等于原模型。

| 模块 | 现有混合整模块 | 真 INT8 计算核 | 加入口/出口 | 相对现有模块 MAE（FP16 值） | 结论 |
|---|---:|---:|---:|---:|---|
| C64 分支 MLP | 0.232 ms | 0.480 ms | 0.605 ms | 0.0793 | 计算本身已慢约 2.1 倍 |
| C128 分支 MLP | 0.224 ms | 0.477 ms | 0.557 ms | 0.1148 | 计算本身已慢约 2.1 倍；pair 核有溢出寄存器 |
| C256 分支 MLP | 0.223 ms | 0.569 ms | 0.651 ms | 0.1289 | 计算本身已慢约 2.6 倍；pair 核有溢出寄存器 |
| 第一 C512 FFN | 0.249 ms | 0.241 ms（i32） | 0.292 ms | 0.0580 | 核内仅省约 0.007 ms，完整边界反而慢 |

原始单模块报告：`D:/Codex-NR-Experiments/nr-b580/pure-int8-branched-mlp-v1/{c64,c128,c256}-single-module.json`、`D:/Codex-NR-Experiments/nr-b580/pure-int8-c512-full-v1/first-c512-full-probe.json`。C64/128/256 各有约 99% 的 FP16 输出值改变；C512 第一块最大差 1.492。当前校准下，画质变化不是可忽略误差，因此未将这些算子组合进产品，也不能把它们称作“纯 INT8 DLSS5 NR 已完成”。

C32 相邻整数计算可直接消费前一个整数输出，省去了中间回转；此前单模块原语测得 i32 整数段约 0.417 ms，仍慢于旧混合段约 0.375 ms，入口和出口额外耗时。两帧十模块技术冒烟通过，但并不等于十模块视频质量通过。只替换 `pre.mlp` 的 243 帧视频技术检查通过，模型计时中位 46.450 ms；该数不是与 42.371 ms 原尺寸基线同轮配对，不能以差值证明变慢。视频位于 `D:/Codex-NR-Experiments/nr-b580/fixed-int8-c32-v1/video/first.mkv`，左右审核片 `first-vs-full-review.mp4` 为 243 帧 24 fps；用户肉眼审核结论为“可接受但面部纹理明显不同”。因此这只是可继续探索的快速版候选，不应作为默认画质。

审核片来源两路无损 RGB 编码各解码 243 帧后，按相同帧号比对，RGB8 绝对误差均值每帧的中位为 **1.313/255**，全 243 帧均值 **1.361/255**；逐帧 PSNR 中位 **41.68 dB**、最低 **35.86 dB**，最大通道差 38/255。该编码后指标仅辅助肉眼审核，不能拿来代替单模块 FP16 误差或原生 4060 比较。

决策：当前这些单模块候选不满足“计算速度或画质至少一项有可用于主线的收益”的门槛，组合测试会让问题更难定位；保留源码和证据，不推广到整模型。这个结果仅否定**本组内核、布局、量化尺度和 B580 实测形状**，不否定经重新设计的 INT8 路线。下一次整数尝试必须先证明连续段的核内吞吐与校准误差满足门槛，不能只省边界转换。

## 流式核复核（同日）

后续流式 pair 内核在 C128/C256 消除了宽核的寄存器溢出，生成代码也确认有真实 INT8 DPAS。其整数输出与独立 CPU 整数参考逐字节一致，但 12 轮交错 GPU Event 配对中，`pair + project` 相对现有混合模块的中位差分别为：C64 BM16 **+0.167500 ms**，C64 BM32 **+0.002084 ms**，C128 BM32 **+0.000625 ms**，C256 BM32 **约 +3.1%**（正值表示 INT8 更慢）。C64 BM32、C128 的非配对组中位数表面更快，配对结果未证实稳定收益。**计时口径修正：**`probe.py` 的流式 `pair + project` 直接使用预先算好的 `qx`，并返回 INT8；现有混合模块从 `features` 开始。因此这不是同接口的完整模块计时，未计 FP16→INT8 入口和 INT8→FP16 出口；流式候选的端到端相对速度仍需单独测量。原始证据见 `D:/Codex-NR-Experiments/nr-b580/pure-int8-branched-mlp-stream-v1/RESULT.md` 及同目录 JSON。

因此流式方案已解决这组内核的寄存器溢出，但维持当前混合精度主线。这里比较的是所测单模块的部分计算，不是完整模型或视频；整数参考一致也不代表与原混合版画质一致。只有在完整连续段（含入口量化、重缩放、下游消费及必要出口）出现可靠配对提速，并完成视频画质审核后，才考虑重新引入纯 INT8。

## 舍入口径

当前纯 INT8 候选没有模拟 FP8/FP16 舍入：矩阵点积为 INT8×INT8→INT32，激活由整数查表完成。`_round_q12` 是把 INT32 累加值按量化尺度重新映射为 INT8 的定点乘法与对称取整，并非复刻原浮点舍入规则；其 INT64 中间乘积、逐通道倍率和取整方式属于**当前候选设计**，不是用户要求保留的语义。CPU 整数参考逐字节一致只验证此候选自身计算正确。用户允许整数计算带来不同舍入与画质变化，因此流式候选未测出收益，不能外推为“速度优先、简化重缩放的纯 INT8”也无收益。后者仍须独立测试速度与完整视频画质。
