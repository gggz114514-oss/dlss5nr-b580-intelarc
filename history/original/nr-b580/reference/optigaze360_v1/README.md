# 480p 人脸视频：240p、360p 与原尺寸快速版对照

本实验只改变快速版 NR 前后的图像处理，不改 NR 权重、精确版或产品节点。输入是同一段已冻结的 864×480、24 帧/秒、243 帧人脸视频。360p 路线把图像缩到 **648×360** 送入现有快速版 NR，再恢复到 864×480；240p 路线为 **432×240**。这两个较小尺寸的内部补边画布由我们推定，不是从 4060 原生 NR 观察到的契约，因此只比较实验效果与速度，不称作精确迁移。

## 这里用到的技术，中文解释

- **降分辨率处理**：先缩小输入图像再运行 NR，以减少模型看到的像素。运动向量也按相同比例缩小，避免帧间位置错位。
- **颜色改变量**：将 NR 后的小图减去 NR 前的小图，得到 NR 对颜色和纹理做出的改动。重建时把这些改动送回原尺寸，而不是直接放大小图的全部像素。
- **原图引导重建**：在小图每个目标位置附近取 3×3 像素，根据它们与原尺寸像素的颜色和位置相似度，估计该像素应当继承多少 NR 改动；最终仍以原图像素为底。这是借鉴 OptiGazeScaler 的低分辨率引导思想所写的独立实验代码，并未移植它的着色器。
- **帧间运动对齐**：用现有运动向量找到上一帧对应位置，参考上一帧的颜色改变量，并将结果限制在当前附近像素的变化范围内，尽量减少闪烁和拖影。六格视频里单列“加帧间运动对齐”供观察。
- **NR256**：项目原有的另一条更激进的小图实验，实际处理区域约为 256×142；它与本次 432×240、648×360 不是同一个尺寸，也不是相同的重建方案。

OptiGazeScaler 文档里的 **ROI** 指“只让模型处理视线附近的局部矩形”；**GazeRoiScale** 是把这个矩形送进模型前再缩小的倍率；**3×3 fit** 是利用附近 3×3 个小图像素估计如何把颜色变化还给原图。我们这次测试的是**整张画面降分辨率**，没有接入视线追踪或局部矩形，也没有实现它的游戏画面抓取、曝光/白点设置或局部矩形边缘修补。相关术语和功能边界见 [OptiGazeScaler 的 DLSS5 说明](https://github.com/hoangmaiwaxyz2772-max/OptiGazeScaler/blob/master/docs/DLSS5.md)。

用户此前观察到 240p 引导重建使画面颜色更深、皮肤纹理更浅，暂时可以保留这种变化。360p 要看这两点是否减轻，并同时检查表情、头发边缘、运动时的闪烁。用户需肉眼审核最终视频。

## 速度口径

主指标是每帧 **输入缩小＋NR 模型＋结果重建** 的中位耗时，单位毫秒。对照原尺寸快速版的每帧模型耗时。采样来自同一 243 帧视频、同一 B580，去掉前四帧，以 GPU 同步后的墙钟时间计；编译、视频解码、CPU→GPU 上传、GPU→CPU 回读、视频编码和音频处理不计入。实验一次同时算普通放大、原图引导、帧间对齐三个输出，因而“重建”时间是这三个实验分支之和，不代表单独启用一种方法的最终产品耗时。

已验证的基线：原尺寸快速版 **42.371 ms/帧**；240p 模型 **43.715 ms/帧**、整条实验链路 **44.398 ms/帧**，吞吐慢约 **4.6%**；360p 模型 **52.373 ms/帧**、整条实验链路 **53.276 ms/帧**，吞吐慢约 **20.5%**；旧 NR256 为 **11.170 ms/帧**，但画质路线不同。完整计算见 D 盘的 `SPEED.md`。
