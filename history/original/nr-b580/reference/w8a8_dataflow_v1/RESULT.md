# 原尺寸 W8A8 量化＋矩阵计算融合结果（2026-09-23）

原尺寸 480×864、243 帧、相同输入/运动/K8/C512/ViT 与 `NR_MOTION_SCOPE=on` 条件下，融合路径相对原 split W8A8 的同步模型调用中位数均值由 47.2288 ms 降为 44.8442 ms，节省 2.3846 ms（5.05%）。四臂 ABBA 输出及重复输出均为 243/243 帧逐字节一致。这证明消除部分独立激活量化和中间 INT8 缓冲开销有效，但不改变旧 W8A8 的输出。

再用独立 FP16/fused/fused/FP16 四臂 ABBA 对照：FP16 XMX 为 41.8366 ms，融合 W8A8 为 45.0854 ms。融合 W8A8 仍慢 3.2488 ms（相对 FP16 +7.77%），两组配对方向一致。尾窗 profiler 设备忙时的两臂中位数均值分别为 33.3415 与 36.5850 ms。所有完整臂均 DiskOnly；帧 4–242 计时排除上传、读回、IO、运动生成和编解码。此处是原尺寸实验入口，并非产品视频吞吐量。

设备侧分项支持剩余差距主要仍在矩阵链路：FP16-a 末三帧平均 `_matmul` 6.877 ms/125 次；fused-a 为 `_fused` 6.480 ms/53 次、回退 `_matmul` 2.778 ms/72 次、残余 `_quantize_rows` 0.722 ms/74 次，合计 9.980 ms，较 FP16 多约 3.10 ms。其他主要算子（如 `_kernel`）时间接近。融合臂完整进程计数中约 49.5% W8A8 调用实际融合；另有 26,244 次 split 回退（含 profiler 重跑）。因此“中间搬运拖慢 W8A8”成立，但当前融合不足以反超 FP16，不能直接进入产品。

FP16 与 W8A8 不是相同输出：两臂间按 255 灰阶计的整体 RMSE 0.469、最大绝对像素差 13.198。融合 W8A8 相对旧 split 则逐字节一致。若未来有更快的 W8A8 候选，仍须与 FP16 同条件测速并按用户要求审核变化视频。这里不宣称与 4060 字节一致。
