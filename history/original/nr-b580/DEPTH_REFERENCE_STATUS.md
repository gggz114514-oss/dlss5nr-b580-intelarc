# Depth input: fixed-reference measurements

The six native depth sequences captured on 2026-09-08 have been authenticated
and analyzed. Under the measured default settings, changing or omitting depth
does not change final RGB bytes or the captured NR front-end tensors.
This is a scoped native-reference result, not general depth support in B580.

## Measurement

- Fixed SF-v2 RTX 40 reference runtime SHA256:
  `6eb209e764f39872625debd6abaf45e2bb6322f6f270f781f70c059ae30b3927`.
- RTX 4060 Laptop, driver 616.86; owned depth host archive SHA256:
  `23625402674704f82f0dfb6648e1c598c978f011dbf7c0d415ea45c1b203c031`.
- Six cases: bound zero, bound one, changing depth field, the same field with
  DepthInverted enabled, moving step boundaries, and no bound depth resource.
- Four 256x256 frames per case, fine synthetic motion, resets `[1,0,0,1]`.
- Style 0, intensity/tone/structure 1, auto-mask and UI correction disabled.
- Each case has an ordinary capture and a separate native kernel trace.
  Uploaded depth readbacks match independently generated NumPy formulas exactly.
  The input color and motion match the prior zero-depth baseline.

All 24 frames have identical raw final RGB bytes to the corresponding
zero-depth baseline. Paired traced/untraced inputs and outputs also agree.
Captured pre skip/down tensor regions and scalar argument bytes 40:216 are
unchanged. Pre texture slots 24 and 32 remain null in these measurements;
current/history/motion bindings and seed progression match the baseline.

Evidence: `reference/depth-sweep-v1-analysis.json`, generated by
`reference/analyze_depth_captures.py`; per-case manifests are
`reference/4060-depth-*-fine-{sequence,trace}-v1.json`.

## Limits and next work

These 24 native comparisons do not add new B580 model runs to the existing
184-comparison backend checkpoint. They do not establish depth behavior with
other presets, masks, UI correction, arbitrary dimensions, or other runtimes.
The backend API has not been changed to silently accept arbitrary depth inputs.
Investigate mask/UI paths and parameter interactions before broadening that
contract. Current whole-model performance and tool integration remain unfinished.
