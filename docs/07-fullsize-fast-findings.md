# 关闭低分辨率输入后的关键发现

本轮目标是解释快速版为何在人脸明暗、细节及整体增强上偏离固定4060参考。结论来自同一段864×480、24fps、243帧（10.125秒）视频；原生4060和B580冻结精确结果全部243帧RGB half字节一致。固定参考身份沿用[来源说明](../PROVENANCE.md)，不是对所有DLSS版本的声明。

## 三条路线必须分开

1. **精确优化版**：恢复的原数值规则，加上保持语义的融合、布局和图执行优化。
2. **原尺寸快速算术**：同样864×480输入输出，保留快速版FP16/INT8规则和冻结量化参数，关闭外部缩小输入与残差重建；本轮采用诊断用逐行分批执行。
3. **NR256实验路线**：864×480先Lanczos2缩为256×142，再上下复制边缘填充为256×256。运动向量面积平均并缩放到低分辨率像素单位，填充区运动为零。取低NR输出减低RGB的half残差，Catmull-Rom放大并加回原图、clamp。**这条路线画面变化很大，仅保留作为实验；早期“可以接受”的视觉意见不等于忠实于原版。**

256×256是模型画布，256×142是有效图像区域；内部FFN的144行批大小又是另一概念。最终输出仍为原视频大小，但模型看到的有效图像细节已经大幅减少。

## 逐步归因

先保留NR256准备/合成，换回精确算术，243帧独立连续历史，仅首帧reset。全片RMSE如下（RGB按0..255计，越小越接近）：

| 比较 | 全帧 | 固定人脸区域 |
| --- | ---: | ---: |
| 当前NR256快速 vs 全尺寸精确 | 4.9353 | 5.9541 |
| 精确算术NR256＋现有合成 vs 全尺寸精确 | 4.7945 | 5.8437 |
| 当前NR256快速 vs 精确算术NR256合成 | 1.3672 | 1.5089 |

固定区域包含背景，不是皮肤分割。分项有交叉项，不能相加或换算为因果百分比；最后一项包含全部快速算术和历史差异，不能叫纯INT8误差。

然后从六个已保存帧做离线残差诊断，CPU复现的输入缩放和合成与GPU结果数值差为零。将**全尺寸精确的增强残差**缩小后按相同方式重建，全画面误差仅0.207–0.663；原精确NR256路线为0.942–5.893。将残差和水平中间存储改为FP32只改变约0.00030–0.00167。直接放大低NR输出在六帧中全部更偏离参考。

这支持“大幅偏差在低分辨率NR输出时已经出现”，而不是主要由最后的残差存储/上采样造成。参考残差实验使用了正确答案，只能诊断，不能部署为修复。尚未逐项隔离填充、运动缩放及历史反馈。

最后按使用者要求直接关闭缩小输入：原尺寸快速完整243帧RMSE降为**2.1609**，视频被确认画面对位。剩余误差仍存在；没有宣称INT8无损或快速/精确等价。

## 正确的速度比较及一次基线纠正

首轮误选未启用本批优化的旧精确路径，得到457.68ms vs95.60ms、约4.79倍。这个数字**不能用于宣称领先精确优化版，已撤回该比较结论**。

重新选择已验证864×480的`branched_exact_v1.session.Session`，确认11项优化配置启用、图调用36次、reset/temporal两个图entry，关闭诊断采样但保留正确性检查。ABBA四个独立进程（fast/exact/exact/fast），共同GPU驻留输入；先预热4帧，再从首帧重新运行32帧，统计帧4..31。每个进程32帧均与自身已审核参考逐字节一致，推理期间禁止编译。

| 路径 | 两次运行中位数 | 两中位数的平均 |
| --- | --- | ---: |
| 原尺寸快速算术 | 90.52555 / 91.41170 ms | 90.968625 ms |
| 精确优化branched | 309.10890 / 309.23585 ms | 309.172375 ms |

同批约**3.3987倍**，快速调用耗时低约70.58%，调用吞吐约10.99 vs3.23fps。计时包含Python、作用域和guard的同步处理调用；排除上传/读回、运动生成、IO和编解码，不是端到端视频速度。历史约94.8ms的精确QKV结果是256×256，不能混入本表；也不把不同批次快速95.6→91.0当作代码优化收益。

## 证据与局限

[机器可读摘要](../evidence/fullsize-2026-09-14.json)保留原报告SHA-256、逐帧指标与配对样本。它是摘录，不是原始完整日志；素材和张量未公开，所以仅凭clone不能独立重现所有数值。

全尺寸适配保留原INT8权重/范围，C512按144行、ViT FFN按64行分批；注意力仍看到全部token，不做空间分块。适配在NR256首帧与旧快速产品逐字节一致，随后全尺寸独立运行，不注入精确中间特征。这个控制不证明所有输入下的适配等价。图形质量结论限于这段素材和已审核输出。
