# 下一步优化：优先原尺寸快速路径

本轮已确认864×480原尺寸快速输出更接近冻结参考，且相对同尺寸精确优化branched有约3.40倍调用吞吐。下一步围绕这条路线推进，不以重新压回NR256作为默认画质方案。

## 1. 固定正确基线和画质合同

保留三条独立路线：精确优化、原尺寸快速、NR256实验。精确路线继续要求冻结参考字节一致；快速路线允许已说明的差异，但新增输出须做逐帧技术检查和视觉复审。任何速度表同时写清后端、尺寸、是否缩放、预热、计时边界和图执行状态。禁止再次用旧默认精确冒充精确优化，也不跨尺寸比较95ms数字。

## 2. 把原尺寸诊断适配变成正常执行路径

- C512当前复用144行INT8内核，ViT FFN复用64行内核，通过多次调用与尾部补零处理完整输入。可尝试原生动态行数/合适tile，减少调用、拼接和临时张量。注意力必须仍覆盖完整窗口/token，不能把按行FFN批处理变成切断注意力上下文的图像分块。
- 评估全尺寸图捕获/重放，保留独立reset/temporal历史、池外输出所有权与参数更新合同。当前诊断是eager执行，不能据此预估图捕获一定有多少收益。
- 将已验证的布局直读、融合量化、decoder gather用于完整尺寸，保留算术舍入和边界。先比较同样输出的端到端NR调用，再决定是否保留候选。

## 3. 定位原尺寸快速版的剩余画质误差

当前全片RMSE约2.16仍非零。固定原尺寸输入及相同历史条件后，分别检查ViT/C512 INT8、FP16矩阵路径及量化范围饱和情况。先做有限边界消融，不直接全网重新量化；局部指标不能冒充完整视频改善。任何新量化都属于新的画质合同。

## 4. 扩展到1080p和产品接口

864×480是本轮实测范围；优先补1080p原尺寸的缓存、显存、时序/控制与画质检查，再测性能。不能把NR256处理后输出1080p的老成绩当成1080p模型成绩。之后再考虑标准1440p/2160p，不以2559×1439边界样例替代。

产品接口需要明确选择精确优化/原尺寸快速/实验缩放、集中离线编译与缓存复用、可配置资产路径、失败可定位。GPU Block/DIS继续沿用项目已验证接口；其私有实现不因研究仓库更新而公开。

## NR256实验保留原则

**画面变化很大，只作为实验路线。** 保留源代码、归因数据和历史结果，允许研究质量/算力取舍；不作为默认忠实模式，不把使用者早期容忍差异解释为与原版相似，也不将原尺寸快速的91ms贴给NR256路线。

本路线图未宣称新增优化已经完成。所有预期收益需同输入、同尺寸、同计时边界验证；本次约11fps仍未达到24/30fps实时。
