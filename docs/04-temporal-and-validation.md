# 时序、运动和验证范围

## 完整时序必须使用自己的历史

隔离算子时可以给B580原生捕获的上一帧或front，以缩小问题；最终时序验收不能这样做。每个B580会话持有自己的上一帧NR结果和seed，连续运行，原生值只在输出之后用于比较。

除了每帧RGB字节，还要检查私有历史、重置、状态推进和输出所有权：

- `[reset, continue, continue, reset]`最后一帧应精确重现首帧。
- 调用方改写返回张量，不得污染模型私有历史。
- 非法运动、尺寸切换或参数失败，不推进seed和历史。
- 保留早期返回值，后续图重放不得覆盖它。
- 不同模式/模型会话的历史独立；只读常量共享必须经过对象、内容及版本检查。

这些检查能发现“画面暂时正确，但下一帧会坏”的后端错误。

## 运动输入与纹理规则

输入运动为**当前帧到上一帧**的像素位移，HWC2，与颜色同分辨率，按原生RG16F纹理量化。用已知平移探针确认方向，再使用零运动、整数、亚像素、跨边界、逐像素变化和估计光流。

原生历史重建采用五个双线性采样点构成十字，按SASS顺序计算cubic权重和归一化。它不等同于普通bilinear或16点bicubic。前端和post还有不同的融合/舍入位置。

固定半精度纹理配置下观察到：两个轴的分数及交叉权重按1/256量化；其余权重由相减得到；仅非零权重texel参与公共指数选择；对齐到14位小数有效位后求和；某些半精度中点远离零。负零也需保留。具体实现见[sampling.py](../backend/nr_backend/sampling.py)。

非2次幂尺寸必须保留尺寸倒数和归一化的舍入，不能代数约去。对正归一化横坐标u和宽W，本次测得的系数计算为：

```text
n = floor(u * 2^21)
coefficient = clamp(((n * W + 4096) >> 13) - 128, 0, (W - 1) * 256)
```

两个轴各229,376个独立基底位置区分了16..24位和不同舍入候选。这是当前纹理配置的实验结论，不能泛化为所有CUDA纹理格式。

历史重采样可产生负RGB。例如一个fractional参考帧有79个负分量，最低约-0.0105972。仅预览PNG可clamp，原始输出比较保留负值。post的`history_numerator * reciprocal - base`还必须保留融合，分成两步曾各留下一个RGB差异。

## 必须公开的抽帧纠错

早期FFmpeg `trim`保留非零起始时间戳，默认CFR输出为填补时间重复首帧。原计划的相邻帧测试实际成为重复截图测试。发现后撤回了相邻视频帧覆盖声明，保留旧文件和运行收据。

受影响的历史比较仍能说明相同实际输入下的历史累积、合成运动、控制和重置行为；不能说明真实画面变化的时序。修正后的抽帧加入`setpts=PTS-STARTPTS`和`-fps_mode passthrough`，再次检查实际解码内容的哈希和帧数。

之后864×480及1920×1080各完成十二个真实相邻画面加首帧重置，共13帧，双方使用同一DIS估计光流，最终RGB和默认历史逐字节一致。1080p某光流分量约258.423像素，超过当时±256接口，扩展到有限half范围±65504并验证拒绝非有限输入后才通过。没有把光流截断来绕过失败。

原始游戏几何运动与图像估计光流不同；Apex重复截图探针也不能冒充真实游戏录像。当前版本的控制/UI测试仍需保留这类素材范围说明。

## 四种证据不要混在一起

| 证据 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 原语域/独立oracle | 特定算术/布局规则在该域下成立 | 完整模型和全部输入成立 |
| 原生front起点的连续前缀 | 后续链条无需中间注入也对齐 | 自己生成front或最终图像已对齐 |
| 原始RGB起点、自有历史的完整模型 | 所记帧及状态的完整结果一致 | 未测控制/HDR/任意尺寸成立 |
| 肉眼审核与有损视频 | 用户是否接受快速路径视觉差异 | 原始浮点或逐字节一致 |

CPU读取保存数组、验证文件哈希和统计，是对证据链的复查；如果没有重新执行数学，不能称为独立CPU模型复现。SHA-256固定文件身份，不能单独证明实验真实或算法普遍正确。
