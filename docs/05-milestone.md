# v0.1.0-pre 的阶段成果

## 精确路径

发布的35个后端文件保持本地精确提交`7355848c4b8952fb5e383fe29d3e2fb3cdd00b1d`的字节；逐文件摘要见[源码清单](../evidence/source-manifest.json)。当前可选Triton路径保留原权重、网络和逐步舍入。

当前版本的正式回归为55帧：256/480/1080运动各13帧，512/480/1080/2559控制/UI各4帧；主目录另13帧480p复验。RGB、相应私有历史、reset、非法输入和调用方修改保护均通过，保存结果被重新读回核对。控制/UI素材受历史重复首帧说明约束。

历史检查点另记录372次参考路径比较、12个优化源码版本累计736次融合比较，以及存档版本的图形共享测试。这些包含重置和重复输入，不能相加宣传为当前源码覆盖1108个独立场景。本版使用逐报告/逐版本索引。

记录的尺寸合同为256×256、512×512、864×480、1920×1080、2559×1439；并不自动允许任意分辨率。已实现的控制、UI、mask入口不等于所有交叉组合和HDR/深度都得到等价证明。

## 快速路径是另一个验收标准

保留原权重和网络主体，使用FP16 XMX或选择性INT8矩阵；NR256残差路线还把整个画面缩小后执行NR，再重建差值。它允许经过视觉认可的差异。NR256是整个画面的低分辨率处理，不是只处理某个ROI。

最新保存的快速源码来自本地`nr/int8`阶段。完整390帧、约6.5065秒的1080p四格视频已获接受；本次原生half FMA优化与该已接受NR256路线的全部低分辨率输出及完整FP32合成哈希一致。未据此宣称与原生NR或精确后端字节一致。

## 与4060还有多大差距

同一256×256原生输入纹理、零运动、默认SDR、输入驻留GPU、完整NR调用与完成的host口径：

| 实现 | 连续帧平均 |
| --- | ---: |
| 4060 Laptop 固定SF-v2 | 3.566807ms |
| B580上一快速候选 | 22.695921ms |
| B580原生half FMA快速候选 | 22.143602ms |

每个B580路径3轮，各180次reset和180次temporal计时。B580约6.208倍耗时，尚未追平4060。4060设备时间戳约2.441643ms是另一个口径，不拿它与B580完整host时间直接相除。

另一个带真实运动及完整1080p残差合成的成对实验，连续帧由23.478818ms降到22.857864ms。本体消融中位数16.982630→16.390900ms，节省约0.59ms。不同实验场景与scope不混合计算速度比，也不把NR256数据冒充全1080p模型速度。

静态主体时序图的B580设备事件区间约16.442411ms，host约16.622670ms。这支持瓶颈主要不在图外Python解释，但事件包含调度空隙。尚未通过硬件占用分析量出中间读写、矩阵利用率、算术补偿的各自贡献。

## 下一里程碑

1. 保持精确分支的既有基准，扩大尚未验证的控制、深度/HDR与输入域。
2. 快速路径优先优化本体：更大块融合、减少中间张量写回、改进矩阵执行；同口径先追平4060。
3. 建立可复用且有清晰所有权的D3D12/Intel执行接口，接入OptiScaler与既有视频工具。
4. 每次改变画质，继续完整视频和人工审核；字节不变的优化使用技术验证。

本版固定已完成的阶段，不宣称“完美迁移”“已实时”或“原生DLSS5全面替代”。
