# 如何把4060变成可核对的计算参考

## 固定实验身份

本研究固定社区 SF-v2 DLL，而不是按文件名认定版本：

| 对象 | SHA-256 |
| --- | --- |
| NR DLL | `6eb209e764f39872625debd6abaf45e2bb6322f6f270f781f70c059ae30b3927` |
| WEIGHTS_HT，147,695,410字节 | `836f445d06ecd2e59bb9f17b84b91c143396fd76ccda1c9dc7fe81d5edd548f4` |
| 首个pre SM89 CUBIN | `676d04897fe88e3b21f766b89da72b85f468fa414835b02a8d9215aaa4fb3b1e` |
| C64所在module3 SM89 CUBIN | `16e4400bfb1c7ffaff42c98ceae3bc95b7cfce3b83b0b891d07faa707afc35b8` |

宿主基于 `video2dlssnr` 固定提交，社区解析研究也固定提交，详见[来源](../PROVENANCE.md)。记录宿主源码、构建输入、可执行文件、运行参数、输入文件与输出文件哈希。更换任一项必须成为新实验，不能把不同兼容DLL的结果混作同一个“真值”。

## 捕获的是模型真正收到的纹理

图像文件相同不保证GPU输入相同。宿主可能先解码、转换色彩、缩放或量化。我们的基础捕获读取实际GPU颜色、深度、运动纹理以及模型输出，位于展示合成之前。

- 颜色纹理：RGBA16F，回读时无损扩展为小端FP32 HWC4。
- 运动纹理：RG16F，以相同方式扩展为FP32 HWC2。
- 深度：R32F。
- 输出保留原始浮点，不为生成PNG而先截断。
- 记录尺寸、padding、reset、seed、style/preset、强度、UI/遮罩等实际参数。

首先比较未插桩宿主和捕获宿主的完整输入与输出字节。只有采集本身没有改变结果，才将其用于后续研究。远程Windows服务会话曾能创建D3D12设备，却在NGX初始化被拒；登录用户的交互会话成功。该失败属于运行环境，不能据此判断4060不支持。

## 原生调用追踪与完整缓冲区

自有宿主内的捕获器记录模块、函数名、grid/block/shared大小、参数payload，以及特定调用前后的完整arena。arena是模型运行时使用的一块GPU工作缓冲区。

发布的[早期捕获器](../reference/native-trace/nr_nvapi_trace.cpp)展示这一方法：只在测试宿主进程中观察调用，不改NR输入或原运行库。其私有NVAPI签名来自公开研究，不是稳定公开SDK契约。后期大尺寸实验提高过捕获预算；此文件不能冒充所有后期版本。

采集预算是诊断的实际限制。例如32MiB单arena上限曾导致未保存中间缓冲区，2GiB总预算曾只允许部分时序边界落盘。必须区分“模型执行成功”和“该边界已捕获”，更不能将未保存的范围计作已验收。

## 独立CUDA重放

将捕获的未修改CUBIN、参数、权重片段、arena初始状态送入自有CUDA Driver API程序。程序只重绑定自身分配的指针，保留其他标量与纹理属性，然后比较整个输出和arena。

例如[C64重放](../reference/native-replay/c64_replay.cpp)以捕获的88字节参数运行4个原始调用，重绑定arena指针偏移0/8/48/64/72和权重偏移16。完整arena15,711,232字节、4个409,600字节层输出及204,800字节down逐步与宿主一致。

这能排除大量假线索：漏掉前序写入、错误输入布局、错误参数偏移、纹理采样属性不符。每份holdout从其自己的原生上游arena出发，不拿一张图的状态替代另一张图。

## 研究副本插桩

只有原始独立重放通过后，才修改**独立提取的研究CUBIN副本**，插入有限寄存器/共享内存dump。原始DLL继续作为完整参考。

操作要求：

1. 保存原CUBIN哈希和修改清单。
2. 明确要观察哪个调用、哪组寄存器和哪段有效输出。
3. 避免临时地址寄存器覆盖仍存活的原值。
4. 等待Tensor Core固定延迟或依赖完成，不能立刻store尚未就绪的寄存器。
5. 用官方nvdisasm回读每条注入指令，确认编码与意图一致。
6. 在诊断输出后停止不再适用的后续计算，避免把dump布局当正常特征继续运行。
7. 用未修改重放和其他独立快照交叉验证dump的正确性。

例如 `pre-mlp1all-dump-v1` 因读取过早无效；v2补足延迟，并与另一有效快照的前16通道一致后，才成为可用参考。C64输入dump的v1在本地反汇编检查被拒，没有部署。这些失败不是B580算法误差。

## 一次可复用的误差定位流程

```text
确认两个实现收到相同实际输入
  → 完整模型找到首个不同调用
  → 证明前一调用及该调用输入一致
  → 独立原生重放复现该调用
  → 二分内部边界：MLP / QKV / normalize / exp / sum / projection
  → 用多种输入推导布局或数值规则
  → 独立oracle及完整输出验证
  → 从原始RGB重新跑完整链，撤掉所有诊断参考输入
```

本仓库分发程序源码和摘要，不分发原始CUBIN、权重片段与捕获素材。完整重做原生实验需要自己准备相同参考环境与资产；仅有报告哈希不能让第三方独立重演全部实验。
