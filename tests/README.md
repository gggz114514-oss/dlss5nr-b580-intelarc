# Portable source checks and offline XPU reproduction

Run from any checkout; no E:, D: or G: layout is required. Python 3.11+ is
required for the stdlib CPU checks. The model, Torch, Triton and Intel driver are
not loaded by `validate_current.py` or the CPU tests.

```console
python -I -B tests/validate_current.py
python -I -B tests/cpu_tests.py
```

`validate_current.py` checks every file SHA/byte count in
`evidence/2026-10-03/current-source-manifest.json`, Python syntax, required local
modules, the actual `FullsizeGameModes` API and its 720p geometry, accepted C512+K8
six flags and control/input contracts. A missing file or bad SHA exits nonzero.
It never treats an incomplete Main extraction as a successful check.

For a separately relocated frozen source inventory:

```console
python -I -B tests/validate_current.py --source-root experiments/2026-10-03/r18/source --manifest tests/registry/r18.json
```

The original absolute `source_root`/row paths are historical provenance. Only
canonical relative paths are used for relocation; SHA and complete inventory
checks remain required. The supplied published relative inventory, not a
hardcoded file count, defines coverage. Generated bytecode omitted from the
publication is listed separately in the relocated registry's provenance.

## Preparation checklist

See [PREPARATION.md](PREPARATION.md). Weights, profile/calibration arrays, LUTs,
the compiled Triton host helpers, Triton-XPU toolchain and Torch are supplied
externally. No asset is downloaded, synthesized or uploaded by these tests.
The source release alone is not a runnable model installation.

The GPU entry is `run_current.py`; it has a CPU-only `--plan` mode. The public
minimum is the installed current720 profile: C512+K8, all six accepted flags,
`unrounded`, fused real pixel motion and graph replay. It calls
`nr_game_fullsize.FullsizeGameModes.select/process` directly. It does not start
a game bridge, control HTTP server, or native game hook.

Synthetic fixed-seed smoke tests establish execution, finiteness and replay
repeatability. They do **not** reproduce the private face-video quality review,
NVIDIA/4060 byte reference, a native bridge, game latency or game FPS.

The public entry has completed a synthetic accepted-current720 run and a
single-repeat paired FDP run on Intel Arc B580. This verifies the documented
offline execution, finite outputs/history, replay, and read-only cache workflow;
the FDP timing is descriptive and is **not** a performance qualification. It
does not qualify private-video quality, native game integration or game FPS.
See the [public GPU reproduction review](../evidence/2026-10-03/reproduction/PUBLIC_GPU_REPRODUCTION_REVIEW.md)
and its compact [receipt](../evidence/2026-10-03/public-review/PUBLIC_GPU_REPRODUCTION_RECEIPT.json).
Other hosts must validate their own GPU/toolchain combination.

## Export and reproduce the current accepted route

Export from your own complete runtime into a fresh directory **outside** the
checkout, development archive and runtime. This command uses only stdlib CPU;
`--plan` inventories without writing. It verifies the installed cfg/profile
agreement and copies every model-asset/table/calibration byte, never to Git.

```console
python -I -B tests/export_assets.py --source-runtime /path/to/your/nr-runtime --output /external/assets.bundle --plan
python -I -B tests/export_assets.py --source-runtime /path/to/your/nr-runtime --output /external/assets.bundle
python -I -B tests/validate_current.py --assets /external/assets.bundle
```

Use a dedicated, matching Torch-XPU Python. The portable runtime's bundled
Python can be passed through `--python`; a compatible isolated venv is also an
explicit option. The source `--runtime-root` is read-only. Binaries/toolchain
come from the exported bundle or this root. No global environment is changed.

```console
python -I -B tests/run_current.py --runtime-root current/runtime --assets /external/assets.bundle --output /external/current-plan --height 720 --frames 13 --repeats 3 --python /path/to/xpu-python --plan
python -I -B tests/run_current.py --runtime-root current/runtime --assets /external/assets.bundle --output /external/current-run --height 720 --frames 13 --repeats 3 --python /path/to/xpu-python
```

Accepted construction includes C512+K8, all six flags **and**
`numeric_cleanup_720={branch_accum_families:[c128], history_value:fp32_fractional,
front_noise:native_both}`. Its base identity is independently calculated with
the actual pinned stdlib option module and must equal
`numeric-cleanup-720-v1:85549e9c272011a4ed4974a4d341f3e28280723afe3dabf29c9dd0d9af043938`.
Selected implementation hook identity is added separately for the composed
suite. Child guards continue to use the base identity.

Each arm has a new portable runtime view, dedicated cache and two serial GPU
children: offline precompile then a fresh process using the real
`fast_cached_runtime_v1.DiskOnly`. Missing readonly keys, source/binary drift,
array differences between this arm's phases or any child/admission/retirement
failure stop the run. Readonly writes are denied and cache inventory compared.
A shared exclusive lock prevents another instance of this public runner from
launching simultaneously; `--gpu-lock` can select an existing coordination
location. It does not kill or manage unrelated processes. Coordinate the slot
with game/other GPU jobs separately.

Both phases process initial13, two warm13 and three measured13 sequences (or
`--repeats N` measured cycles). Only frame0 resets. Every output and private
history is finite/hash checked; only the initial13 tensors are saved. Warm
cycles persist summaries, not duplicate arrays. Graph routes prove 2 captures,
11 initial replay routes; the graph object's counter also counts its capture
frames. Raw50 directly replays one immutable captured body, without changing
frame/history semantics or Python dispatch counters.

Full process events surround `FullsizeGameModes.process` including prep,
history, commit and composite; they also include stream idle while Python
submits. Raw body events exclude those outer stages. Input creation/load/H2D,
readback/hash/save and event setup sit outside both timing boundaries. CPU wall
times are separate. Exclusive private-stage device times remain unknown.

## Candidate versus matching frozen baseline

```console
python -I -B tests/run_current.py --assets /external/assets.bundle --output /external/fdp-pair --python /path/to/xpu-python --candidate fdp
python -I -B tests/run_current.py --assets /external/assets.bundle --output /external/qkv-pair --python /path/to/xpu-python --candidate native_qkv
python -I -B tests/run_current.py --assets /external/assets.bundle --output /external/vit-pair --python /path/to/xpu-python --candidate rowonce_vit
python -I -B tests/run_current.py --assets /external/assets.bundle --output /external/swin-pair --python /path/to/xpu-python --candidate swin_serial_split
```

Aliases select **existing** r18 constructor records: `fdp`, `native_qkv`,
`rowonce_vit`, `swin_serial`, `swin_split`, `swin_serial_split`. Any exact r18 arm
name is supported, with its actual controls and hooks. Registry/source pins
are checked before launch. `--candidate` runs a baseline with identical controls
first, then the candidate; all GPU children are serial. An `--arm` is a single
arm from `--source-root` / `--manifest`; `--baseline path/to/readonly/RESULT.json`
can pair already saved results. Pairing verifies all input, reset, seed, control
and measured frame-count contracts before MAE/max/PSNR/changed-pixel comparisons
of complete outputs **and private histories**. Numerical candidate differences
are reported without a fabricated quality pass or a 1ms performance cutoff.
Style0 does not qualify style1/2. Low strength needs a separate real native
adapter context and is rejected here.

## External NPY and historical references

`--inputs /external/inputs.json` replaces the generator. Schema:

```json
{"schema":"nr-release-inputs-v1","scenario":"user supplied sequence",
 "height":720,"width":1280,
 "motion_contract":"current-to-previous pixel displacement",
 "frames":[{"ordinal":0,"reset":true,
   "rgb":{"path":"rgb-00.npy","sha256":"FILE_SHA","raw_sha256":"PAYLOAD_SHA"},
   "motion":{"path":"motion-00.npy","sha256":"FILE_SHA","raw_sha256":"PAYLOAD_SHA"}}]}
```

Supply all 13 ordered records; only ordinal0 resets. Arrays are C-contiguous
little-endian float32, RGB `(720,1280,3)` in `[0,1]`, motion `(720,1280,2)` in
pixel displacement, all finite. Paths are relative to inputs.json. The CPU
validator checks NPY headers, exact payload lengths and file/raw SHAs without
NumPy; object arrays, Fortran order, NaN/Inf and unsafe paths fail.

`run_historical.py --bindings /external/bindings.json --output /external/run
--candidate fdp --python /path/to/xpu-python --plan` accepts schema
`nr-release-historical-bindings-v1`; fields `repo_root`, `runtime_root`, `assets`,
`source_root`, `manifest`, `inputs`, `legacy_root` and `original_fixture` bind
roots relative to that JSON's directory. Its reference schema hashes immutable
`tests/legacy/phase2` files, the original fixture receipt when supplied and the
frozen arm registry. Execution uses this public harness and the byte-authenticated
archived model/constructor; **it does not claim an unmodified private PHASE2
supervisor run**. The original supervisor's V4/PHASE1 receipts, immutable READY,
private fixed13 NPZ material and private historical dependency trees are still
needed to run that original harness directly. They are not silently replaced.
Historical timing summaries are references; a new synthetic pair is a new result.
